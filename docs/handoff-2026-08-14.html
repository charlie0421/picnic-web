2. 가장 중요한 발견 — never 붕괴의 원인 해결됨

원인은 패키지 세대 불일치였다.

@supabase/ssr@0.6.1 은 반환 타입을 SupabaseClient<Database, SchemaName, Schema> 3-슬롯으로 하드코딩하는데, 설치된 @supabase/supabase-js@2.86.2 의 SupabaseClient 는 <Database, SchemaNameOrClientOptions, SchemaName, Schema, ClientOptions> 5-슬롯이다. ssr 이 3번째로 넘기는 Schema 객체가 신형의 SchemaName(제약: string & keyof ...) 슬롯에 대입돼 TS2344 제약 위반이 나는데, 위반 지점이 node_modules 의 .d.ts 안이라 skipLibCheck: true 가 진단을 삼킨다. 그 결과 Schema 슬롯이 never 로 떨어지고 .from() 의 행 타입이 전부 never 가 됐다.

소셜 프로필 자동 갱신은 존재한 적이 없다. #61 커밋 메시지에 "이제 반영된다"고 썼으나 틀렸다. 컬럼만 고쳐서는 동작하지 않는다 — 경로가 네 겹으로 막혀 있었다(#62 에서 규명·제거):

  1. 이 코드는 서버에서 돈다(app/api/auth/exchange-code/route.ts → handleCallback). 그런데 fetch("/api/auth/google") 로 상대 URL 을 써서 Node 가 Failed to parse URL 로 throw 하고 catch 가 삼켰다
  2. Google 은 애초에 도달하지 못했다 — exchange-code 가 id_token 을 apple 일 때만 params 에 담는다
  3. provider/provider_id 컬럼 부재 → 실행됐어도 42703
  4. localStorage 참조 분기 — 서버에는 없어 항상 건너뜀

#62 에서 갱신을 되살리지 않고 제거했다. nickname·avatar_url 은 사용자 소유 데이터다 — 앱에서 닉네임은 update-nickname Edge Function 으로, 아바타는 avatars 스토리지 업로드로 직접 바꾼다(my_profile.dart:160-176). 로그인마다 소셜 값으로 덮으면 사용자가 설정한 사진이 사라진다. 남은 동작은 프로필이 없을 때만 생성하는 폴백뿐이고, 정상 경로는 트리거 handle_new_user() 가 처리한다.

실측(auth/v1/admin/users 40명): Google 14명 전원 avatar_url·picture·full_name 보유, Apple 26명 전원 없음. 즉 "소셜 아바타 갱신"은 애초에 Google 한정 기능이었다. 다시 만들 거라면 자동이 아니라 사용자가 명시적으로 실행하는 동작이어야 한다.

4. 반드시 알고 있어야 할 계약

wallet.v1 — 금액은 전부 decimal string

star, bonus, cotton, delta, total_count 는 모두 문자열이다. MAX_SAFE_INTEGER 초과 값이 실재하므로 Number()·parseInt() 금지. 합산은 BigInt, 표시는 formatWalletAmount().

voting-v2 — 정확히 4개 키

{ vote_id: number, vote_item_id: number, amount: string, request_id: uuid }

키가 더 있으면 Edge Function 이 400 Invalid vote payload. BFF(app/api/vote/submit/route.ts)는 snake_case 로 구조분해한다.

request_id 는 서버 멱등성 키

서버가 대신 생성하면 응답 유실 후 재시도가 매번 새 작업이 되어 이중 차감이 난다. BFF 는 누락·오형식을 400 으로 거절한다. 클라이언트는 lib/wallet/vote-request-id.ts 가 module-scope Map + sessionStorage 2단으로 보존한다. 잔액 사전검증은 하지 않는다 — 멱등 재생을 가로막는다.

5. 함정

npm run build 를 쓰지 마라. prebuild 훅이 VERCEL != 1 일 때 types/supabase.ts(6,000줄+)를 덮어쓰고, postbuild 가 Sentry release 를 만든다. ./node_modules/.bin/next build 를 쓴다.

이 레포에는 Vercel Preview 배포가 없다. vercel.json 의 git.deploymentEnabled 가 { main: true, production: false } 다. 머지 전 눈으로 확인할 방법이 없다. 검증은 로컬이 전부이고, 로그인 필요 화면과 브라우저 시각 검증은 머지 후 Production 에서만 가능하다. PR 본문에 "미수행"으로 명기하고 사용자에게 확인을 요청할 것.

.next 캐시 주의. 브랜치를 리베이스하거나 라우트가 삭제된 뒤에는 .next/types 의 옛 라우트 shim 이 남아 tsc 가 존재하지 않는 모듈을 못 찾는다고 실패한다. rm -rf .next tsconfig.tsbuildinfo 후 재실행하면 사라진다. 실제 오류가 아니다.

  • 빌드가 public/sitemap*.xml 을 수정한다 → 커밋 전 git checkout -- public/
  • Route Handler 는 HTTP 메서드와 세그먼트 설정만 export 할 수 있다. 헬퍼를 route.ts 에서 export 하면 tsc·vitest 는 통과하고 next build 에서만 깨진다 → lib/ 로 분리
  • __tests__/** 는 tsconfig 에서 제외돼 타입 검증이 안 된다 → 컴파일 범위 안의 *.type-test.ts 를 쓴다
  • jsdom 에서 vi.spyOn(window.sessionStorage, …) 는 가로채지 못한다 → Storage.prototype 에 걸 것
  • 이 레포에 supabase/migrations/*.sql 을 추가하지 마라. 스키마는 picnic-supabase 소유 (project ref xtijtefcycoeqludlngc)
  • Node 는 24 로 통일됐다 — engines: {node: "24.x"} + .nvmrc 24.18.0 + Vercel 대시보드 24.x. engines 는 대시보드를 항상 덮어쓴다. 패치 하한(>=24.18.0)을 걸면 Vercel 이미지 미달 시 빌드가 하드 실패하므로 메이저 고정을 쓴다. vercel project update CLI 로는 Node 버전을 못 바꾼다(대시보드·REST API 만)

6. 남은 작업 없음

백로그를 모두 비웠다.

  • @supabase/ssr 업그레이드(#61) — 0.6.1 → 0.12.4, supabase-js 2.86.2 → 2.112.3. §2 의 격리 캐스트 제거. 3-슬롯 버그는 0.6.x 한정이었고 0.7.0 부터 2-슬롯이다
  • lockfile 이중화(#60) — 7개월 방치된 pnpm-lock.yaml 제거. 빌드 로그가 Skipping build cache since Package Manager changed from "pnpm" to "npm" 로 확인해줬다 — Vercel 이 그동안 pnpm 으로 인식하고 있었다
  • legacy-peer-deps 해제(#63) — .npmrc 를 통째로 제거했다. 막고 있던 next-auth/@auth/core 가 참조 0건인 죽은 의존성이라 함께 지웠다(인증은 전부 Supabase 커스텀 라우트)

이제 npm 이 peer 충돌을 검사하므로, 어긋난 조합이 설치 단계에서 걸린다 — 이번 never 붕괴의 뿌리가 막혔다.

lockfile 이 통째로 재생성됐다. 다른 작업 중인 브랜치가 있으면 npm ci 를 한 번 돌려야 한다.

재생성이 회귀를 하나 드러냈다 — react-error-boundary 6.0.0 → 6.1.3 에서 FallbackProps.error 가 any → unknown 으로 좁혀졌다. VoteErrorFallback 에서 instanceof 로 좁혀 처리했다(#63). 같은 패턴이 다른 라이브러리에서도 나올 수 있다 — lockfile 을 재생성할 때는 tsc 를 반드시 다시 돌릴 것.

다음에 할 만한 것

  • tsconfig 의 skipLibCheck: false 상시화 — 이번 never 붕괴를 은폐한 것이 이 옵션이다. 현재 켜면 framer-motion·next·rolldown 등 무관한 서드파티 타입 11건이 뜨므로 그 처리 방침을 함께 정해야 한다
  • .env.local 의 NEXTAUTH_URL/NEXTAUTH_SECRET 플레이스홀더 정리 — 추적되지 않는 로컬 파일이라 각자 지우면 된다

참고 — 손대지 않기로 한 것

  • app/api/uploads/presign — 유일 caller 였던 community PostEditor 가 삭제됐지만, 인증 필요 endpoint 라 외부/Flutter caller 를 이 레포만으로 반증할 수 없다. 프로덕션 접근 로그 확인 후 제거하거나 JSON 410
  • utils/api/queries-vote.ts 의 camelCase 별칭 — 런타임을 바꾸지 않으려고 타입(VoteWithCamelAliases)으로 표현만 했다. 소비자는 테스트 1곳뿐이라 별도 작업으로 한 번에 걷어내는 편이 낫다
  • 배포 DB 의 RLS 를 is_admin_or_super 기준으로 맞출지 — vote_pick 의 SELECT 정책은 auth.uid() = user_id 뿐이라 관리자 예외가 없다. 앱 필터보다 RLS 가 엄격해 fail-closed 이므로 급하지 않다. 참고로 자기 권한 상승은 트리거 trg_guard_user_profiles_protected 가 막고 있다

7. 이번에 값을 치르고 배운 것

테스트가 결함을 잠그고 있는 사례를 두 번 만났다.

RankingView.test.tsx 는 detail 모드가 크래시하는 것을 expect(() => render(...)).toThrow() 로 고정하고 있었다. 동작이 아니라 결함을 잠근 테스트다.

투표 필터 작업에서 내가 처음 넣은 테스트 12개도 상수·헬퍼만 검증해서, 잘못된 색 3개와 잘못된 정렬 컬럼이 12/12 통과했다. 리뷰어가 지적해 실제 결함을 잡는 테스트로 교체했다(렌더된 DOM 의 rgb() 실측, mock 체인의 .order() 호출 순서).

교훈: "상수가 이 값이다"를 확인하는 테스트는 그 상수가 틀렸을 때 알려주지 않는다. 외부 기준(앱 소스)이 있으면 그 기준에서 파생된 관측 가능한 결과를 검증해야 한다.

교차 리뷰가 실제로 값을 했다. 매번 다른 모델이 앞 단계를 반박했다.

  • 인벤토리가 /media 를 삭제 후보로 올림 → 위험 감사가 "VOTE 포털 공개 서브메뉴"라고 반박. 반박이 맞았다
  • 위험 감사가 QNA 삭제 시 concert2025 예약 CTA 가 끊긴다는 걸 발견
  • 최종 리뷰가 상태 점 색 4개 중 3개가 근사값이고 Admin 2차 정렬이 앱과 다르다는 걸 잡음 — 앱 원본(ui/style.dart, prod.json)으로 확인하니 맞았다
  • 권한 리뷰가 !!(a || b) 의 fail-open 을 지적

앱을 요약하지 말고 조건문을 그대로 읽어라. 앱의 area 우선 정렬을 "ALL 탭에서 kpop 우선"으로 요약했는데, 실제 조건은 area == 'all' && finalSort == 'id' 이고 finalSort 가 'id' 로 남는 건 debug(=웹 admin) 상태뿐이었다. 요약대로 구현했으면 일반 탭 목록 순서가 앱과 달라졌을 것이다.

Orca dispatch --inject 텍스트가 부팅 중 워커에서 삼켜진다. Claude·Codex 양쪽에서 재현됐다. terminal wait --for tui-idle 가 satisfied 여도 초기화 중이면 발생한다. 디스패치 직후 terminal read 로 실제 실행(Working·컨텍스트·비용)을 확인하고, 삼켜졌으면 지시서를 파일로 써서 짧은 프롬프트로 재전달한다. 단, terminal send 재전달은 lifecycle capability 를 주입하지 않아 worker_done 이 dispatch_capability_invalid 로 거부된다 → 보고서를 직접 읽고 task-update --status completed 로 복구 정산.

또 워커를 새 워크트리에 띄울 때 .claude/settings.local.json 을 복사하지 않으면 dontAsk 모드에서 tsc 조차 실행하지 못하고 조사 결과가 실측 없이 나온다. 실제로 한 번 당했다.
