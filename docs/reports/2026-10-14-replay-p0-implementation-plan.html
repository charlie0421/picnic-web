Replay P0 구현 계획

2026-10-14 · 구현 전 계획 · 기준 코드 ec2275f6 · 설계 dc3a0ebb · 제품 변경 없음

Goal: 합성 화면에서 Replay의 정상 3구간 전송과 폐쇄 후 네트워크 차단을 검증하고, SDK 정리의 한계를 분리해 기록한다.

Architecture: Next.js와 분리한 정적 HTML에서 고정 SDK를 로드한다. 제어 모듈, 엄격한 P0 변환 Worker, 전용 전송기를 연결하고 로컬 수신 bytes를 별도 검사한다. 정상 이벤트는 위임 transport로 보내되 Replay 연결 정보를 제거한다.

Tech Stack: Node 24.x, TypeScript, lockfile의 Sentry 9.47.1, esbuild 0.28.2, Playwright 1.63.0, Vitest 4.1.11, 설치된 PostCSS. 새 의존성이나 lockfile 변경을 계획하지 않는다.

Spec: Replay 제한 수집 설계 §7의 P0와 그 절이 참조하는 §3–6. 수집 정책 초안도 함께 읽는다.

Agent execution: 이 세션에서 superpowers:executing-plans로 순차 구현하고, 마지막에 다른 공급자의 Frontier 리뷰를 받는 방식을 권장한다. 각 단계는 체크박스로 추적한다. 네이티브 하위 에이전트를 만들지 않는다. Orca 작업자가 필요하면 새 usage-aware Route와 계정·권한 검사를 통과해야 한다.

상태: 사용자는 설계를 바탕으로 계획 작성 진행을 승인했다. 2026-10-14 사용자가 이 계획의 순차 구현도 승인했다. SDK 일시 보관을 관측하는 합성 시험의 계획이며, 운영에서 그 보관을 수용한다는 승인이 아니다. 초기 독립 검토는 사용량 증거 충돌로 시작되지 않았다. 이후 새 관측으로 검토를 실행했고, 구현과 1회 수정 재검토까지 완료했다. 최종 판정은 APPROVE다. 실행 결과와 남은 한계를 참조한다.

Global Constraints

  • 제품의 Replay 기본값 0/0을 유지한다. app/, public/, instrumentation-client.ts, 운영 설정을 변경하지 않는다. 실제 로그인·광고·API·Sentry 저장을 사용하지 않는다.
  • P0 HTML tag는 html/head/body/style/div/span/button, class는 fixture/track/card/toggle만 허용한다. Next head/announcer/shadow root·전역 CSS·CDN·window.Sentry를 사용하지 않는다. script는 SDK 출력에서 생략되어야 한다. HTML charset은 HTTP 응답에 지정한다.
  • 정적 CSS는 .fixture{display:block}.track{display:flex}.card{width:100px;height:100px}.toggle{display:block} 한 개다. raw와 실제 SDK 정규화 표현의 해시를 검토 후 고정한다. 실행 중 처음 본 값을 신뢰하지 않는다.
  • 동적 CSS는 width/height 0…1000px 정수, opacity 0…1의 0.01 단위, --banner-current-index 0…2 정수다. 문자열·diff tuple·빈 priority/important·false 삭제·null 전체 삭제를 지원한다. 허용 목록 밖 속성/값이면 종료한다.
  • 압축 전·후 입력/출력 각각 8 MiB, JSON depth 80, 순회 값 200,000개, 이벤트 10,000개/segment, 노드·차단 ID·tombstone 합계 20,000개다. class 256자/token·64개/node, text 4096자/node다.
  • Worker 2초, fetch 5초, 녹화 5분. 한 envelope만 처리하며 원본 대기 큐·자체 전송 재시도는 없다. 종료한 document는 정상 제어 경로에서 다시 시작하지 않는다.
  • viewport 1…4096, 포인터/scroll −65536…65536 정수, 세션 상대 시간 0…300000ms다. SDK wire의 ms/seconds/relative offset 차이는 실제 샘플로 고정한다. envelope/event의 timestamp는 seconds, rrweb timestamp는 ms이며 mousemove positions의 timeOffset은 event timestamp에 더한 ms로 검사한다. 실제 SDK 관측이 다르면 변환을 진행하지 않는다.
  • 필수 양성 시험은 실제 SDK가 생성한 동일 Replay의 연속 segment 0→1→2다. 전부 거부하는 구현은 실패다. SDK 버전·bundle hash·Git SHA를 결과에 남긴다.
  • 공개 stop의 flush·processor 재시도는 즉시 메모리 제거를 보장하지 않는다. 유한 실패의 60초 정리 목표와 무한 대기의 예상 실패를 구분한다. 이미 전송한 bytes 취소·물리 메모리 소거를 주장하지 않는다.
  • 보고서에는 고정 reason/count/수치만 둔다. 원문 payload·URL·selector·에러 메시지를 진단으로 다시 전송하지 않는다. 합성 raw fixture만 저장할 수 있으며 실제 사용자 자료는 입력하지 않는다.

Review Focus

  1. 정상 HTML에 SDK/브라우저가 추가한 script/head 노드 때문에 전부 거부되는 경우 → Task 1·5의 실제 녹화 양성 경로로 발견한다.
  2. import/Worker/fetch 완료가 close 뒤에 도착하는 경우 → Task 3·4의 세대 검사와 네트워크 시작 0회로 고정한다.
  3. 실패한 segment가 node/sequence 상태를 먼저 바꾸는 경우 → Task 2·4의 trial state 및 성공 후 commit으로 고정한다.
  4. SDK listener 순서·기존 span DSC 때문에 일반 event/baggage에 Replay ID가 남는 경우 → Task 4·5에서 녹화 중과 종료 후 실제 outgoing bytes/headers를 검사한다.
  5. 타임아웃·예상 실패를 모두 성공으로 집계하는 경우 → Task 5·6에서 네 가지 판정 필드를 분리하고 정상 전송의 실패는 exit 1로 고정한다.
