1. 이번에 확인한 범위

  • 직접 작성된 style 사용은 127곳이다. 객체 리터럴에서 속성 이름 56종을 찾았다. 변수·조건식을 참조한 6곳은 별도로 본문을 읽었다.
  • <style>는 9곳이며, HTML/SVG 태그의 prop spread는 6곳이다. 라이브러리 내부·spread·서버 HTML이 만드는 속성은 직접 JSX 집계만으로 확정할 수 없다.

3. 가능한 방향과 추천

방향장점한계
추천: 공개 화면 일부 + 명시적 허용 기준먼저 검증할 범위가 작다. 정적 스타일과 필요한 상태 변화를 보존할 수 있다.개인 화면·구매·실제 투표 제출 문제는 재생할 수 없다. 허용 목록과 버전별 검증이 필요하다.
전체 화면을 대상으로 허용 기준 구현디버깅 범위가 넓다.인증 전환·결제·문의·서버 HTML·외부 SDK를 모두 다뤄야 한다. 현재 증거로 활성화할 수 없다.
Replay를 계속 끄고 오류·성능 이벤트 활용Replay 전용 개인정보·유지보수 부담을 늘리지 않는다.사용자가 본 화면의 변화는 재생할 수 없다. 기존 이벤트 수집도 별도의 개인정보 기준을 따른다.

추천안의 첫 검증 대상은 인증 초기화가 끝나 비로그인이 확인되고, 광고 미동의·광고 SDK 미로딩 상태인 투표 목록 화면이다. 인증·동의 상태가 미확인이면 Replay integration 로드와 녹화 시작을 허용하지 않는다. 로그인·개인 프로필 또는 광고 DOM이 반영되기 전에 수집을 막고 버퍼를 폐기할 수 있어야 한다. 같은 URL에서 상태가 바뀌는 경우에도 적용한다. 광고 동의 여부를 Replay 수집 동의로 간주하지 않는다.

근거: Header.tsx:20·:138과 MobileNavigationMenu.tsx:65·:216은 비동기 인증 결과에 따라 아바타·잔액·사용자 메뉴를 표시한다. components/client/ads/ConsentAwareAdsense.tsx:45·:104는 동의 상태에 따라 광고 스크립트를 삽입한다. 지원 언어·쿼리·상세·모달을 자동으로 포함하지 않는다. 현재 운영에서 시작하지 않고, 합성 데이터로 만든 격리 환경에서 기준을 구현·검증한 뒤 범위를 정한다.

4. 수집 허용 기준 초안

아래는 구현 전 요구사항이다. 관측한 속성 이름을 그대로 허용 목록으로 옮기지 않는다. 허용하지 않은 값은 비우거나 제외하며, DOM 관계를 유지할 수 없는 형식은 전송을 차단한다. 한 구간만 버리고 다음 변경 이벤트를 무조건 전송하지 않는다. 복구 기준은 아래 적용 계층 항목에서 정한다. 실제 페이지 DOM은 수정하지 않는다.

데이터허용 후보제외·변환 기준
녹화 구조검증된 rrweb 이벤트 형식, 숫자 노드 ID와 부모 관계, 화면 크기·스크롤·포인터·시각알 수 없는 이벤트·키·플러그인 데이터를 기본 허용하지 않는다. 노드 ID는 HTML의 id 속성과 구별한다. 삭제로 참조 무결성이 깨지면 전송을 차단하고 녹화 상태를 초기화한다.
텍스트·입력기존 마스킹 결과만실제 텍스트·입력·자유 형식 aria/title/alt 문자열을 허용하지 않는다. unmask 예외를 추가하지 않는다. 마스킹된 길이·공백·입력 여부와 동작 기록도 남는다는 한계를 명시한다.
class·HTML id·참조검토한 빌드에 포함된 정적 class와 필요한 상태 class. 필요한 ID 관계는 녹화 안에서 일관된 대체 ID문자열 모양이나 jsx- 같은 접두어만으로 허용하지 않는다. 서버 데이터에서 만든 class·id, aria-controls·for 등의 원문 참조는 제외하거나 함께 치환한다. 치환 시 CSS 선택자 관계도 검증한다.
상태 속성hidden, disabled, aria-expanded 등 필요한 boolean·고정 enum이름과 값 모두 검사한다. 이름이 허용되어도 임의 문자열은 제외한다. value와 개인 선택을 드러내는 상태는 초기 범위에 포함하지 않는다.
data 속성화면 복원에 필요함이 입증된 개별 이름과 고정 값만data-* 전체 금지. data-testid도 관측됐다는 이유로 남기지 않는다. 광고·SDK 버전·사용자 식별 속성은 초기 범위에서 제외한다. headless UI 등의 상태는 실제 사용 시 별도 enum으로 검증한다.
주소탐색 이벤트의 검증된 고정 경로명, 필요한 경우 매개변수를 제거한 라우트 템플릿query·fragment 제거만으로 충분하지 않다. 경로·userinfo·검색어·리다이렉트 값도 제외한다. 클릭 재생에 불필요한 href·form action은 비운다. 알 수 없는 주소는 전부 제외한다.
미디어·외부 리소스차단 placeholder의 크기. 검토한 빌드의 정적 글꼴 등 꼭 필요한 자산만 별도 후보이미지·SVG·영상 차단을 유지하고, 모든 iframe을 초기 범위에서 차단한다. placeholder에 남는 class에도 class 허용 기준을 적용한다. CSS 배경 이미지는 별도 경로이므로 url()·@import·data/blob URL도 검사한다. 도메인 일치만으로 사용자 업로드·서명 주소를 허용하지 않는다. 광고 미동의·SDK 미로딩 조건을 유지하지 못하면 녹화를 중단한다.
Replay DOM breadcrumb필요한 경우 검증된 이벤트 종류·시각·숫자 nodeId만ui.click·키 입력 관련 breadcrumb·ui.slowClickDetected·ui.multiClick의 message와 data.node의 원문 text/attributes를 초기에는 제거한다. data.url·route는 제거하거나 검증된 고정 라우트로 바꾼다. 필요성이 없는 종류는 이벤트 전체를 제외한다.
네트워크·console·사용자 메타데이터필요성이 입증된 요청 메서드·상태 코드·시간·라우트 템플릿만기본 수집되는 performanceSpan의 resource/navigation/fetch/XHR name·url·previous를 포함해 원문 주소를 제거하거나 고정 라우트로 바꾼다. 요청·응답 본문, 헤더 값, console 자유 문자열, 사용자 ID·이메일·tags/extra 임의 문자열은 초기에는 제외한다. replay_event와 다른 custom event에도 같은 기준을 적용한다.

CSS는 정적 산출물과 동적 값을 구분한다

  • 정적 CSS: 검토한 release의 CSS·styled-jsx를 기준으로 허용한다. 파일 URL뿐 아니라 전송되는 내용의 일치도 검증해야 한다. rrweb이 인라인화·정규화한 표현과 CSSOM 변경 이벤트를 포함한다. 빌드 원문 해시와 녹화 문자열 해시가 같을 것이라고 가정하지 않는다.
  • 동적 CSS: 필요한 속성별로 숫자 범위·단위·고정 enum·제한된 함수 문법을 정의한다. 예: 배너 인덱스는 검증된 슬라이드 범위의 정수, opacity는 0–1, 위치·크기는 제한된 단위의 유한 수, 색상은 정해진 팔레트. 수치 범위와 변환 정밀도는 구현 설계에서 화면 요구에 맞춰 확정한다.
  • CSS 변수: --banner-current-index, --banner-slides-per-view, 전역 RGB 변수 3개를 우선 검토한다. --tw-*는 65개를 관측했지만 접두어 전체를 허용하지 않는다. 정적 빌드 값과 필요한 동적 변경을 따로 검증한다.
  • 자유 문자열 경로: content, attr(), 임의 var() 참조·fallback, URL·이스케이프 문자열·미확인 custom property는 제외한다. 정적 산출물의 필요한 빈 content·고정 변수 참조는 검토된 내용에 한해 다룬다. CSS.supports() 통과는 개인정보 검증이 아니다.
  • 모든 CSS 입력: inline style, style 텍스트, 링크의 _cssText, 규칙 추가·교체·선언 변경, adopted stylesheet, 글꼴 이벤트를 함께 확인한다. 기존 알려진 예외 6개와 잔여 반례도 이 기준으로 다시 검사한다.

숫자·enum만으로도 모든 정보 유출을 수학적으로 막을 수 있는 것은 아니다. 검증된 앱의 화면 구조와 필요한 시각 상태로 범위를 제한하는 정책이며, 임의 스크립트가 모든 DOM 상태에 정보를 인코딩하는 적대적 환경까지 안전하다는 주장은 하지 않는다.

적용 계층과 실패 처리는 후속 설계에서 확정한다

DOM·CSS 허용 기준의 구현 위치는 아직 확정하지 않았다. 후보는 기존 최종 전송 필터의 확장과 녹화기 수준의 변경이다. 전자는 압축·크기·2초 처리 한도와 여러 구간의 노드 상태를 처리해야 한다. 후자는 현재 SDK의 공개 설정만으로 모든 필드를 다룰 수 없으므로 지원 범위·업그레이드 비용을 검증해야 한다. custom event 필터는 별도로 적용할 수 있으나 DOM 필터를 대체하지 않는다.

실패 시 요구사항: 필터 적용 후에도 허용 기준이 성립하지 않거나 예외·한도 초과·인증/광고 상태 변화가 발생하면 먼저 전송을 차단하고, 녹화를 중단하며, 대기 중인 원본 버퍼·전송 큐를 폐기한다. stop()이 flush를 유발할 수 있으므로 메서드 호출만으로 폐기됐다고 간주하지 않는다. session 모드는 기본적으로 주기적 full snapshot을 생성하지 않으므로, 손상된 구간 뒤의 변경 이벤트를 계속 보내면 안 된다. 재개는 검증된 새 full snapshot과 초기화된 ID 상태에서만 허용한다. 전송 차단·큐 정리·재개의 정확한 SDK 제어 방식과 제한된 시간 안의 처리는 구현 설계에서 증명해야 한다.

5. SDK 9.47.1에서 주의할 점

  • beforeAddRecordingEvent는 이 버전에서 isCustomEvent(event)일 때만 호출된다. DOM 스냅샷·DOM 변경 전체를 걸러 주는 훅으로 설계하면 안 된다. node_modules/@sentry-internal/replay/build/npm/esm/index.js의 maybeApplyCallback을 확인했다.
  • Replay 자체 DOM breadcrumb·performanceSpan은 custom event 경로다. 위 훅에서 축소·제외할 수 있는 대상으로 검증한다. 앱의 beforeBreadcrumb와 DOM 속성 마스킹만으로 이 경로가 모두 제거된다고 가정하지 않는다.
  • 기본 maskAttributes는 title, placeholder, aria-label이다. 이 버전의 구현은 maskAllText에도 의존한다. 최신 문서의 동작을 이전 SDK에 그대로 적용하지 않는다.
  • 녹화기의 maskAttributeFn은 src·href·srcset·style 등 먼저 정규화되는 속성에 일반 필터로 적용되지 않는다. 이 훅만으로 DOM·CSS 허용 기준을 구현할 수 없다. 기본 slimDOMOptions: 'all'이 script·preload·소셜 meta 등을 제외해도, 남는 head의 meta content·link href·hreflang 등에는 별도 기준이 필요하다.
  • SDK는 stylesheet 인라인화와 글꼴 수집을 내부 기본값으로 사용한다. 공개 설정에 없는 옵션을 추가하면 작동한다고 가정하지 않는다. 최종 전송 단계의 필터와 실제 SDK 녹화로 확인한다.
  • 기본 iframe 차단은 iframe[srcdoc]:not([src]) 등 일부에 한정된다. 차단되지 않은 cross-origin iframe은 rr_src에 주소가 남을 수 있다. 초기의 모든 iframe 차단 요구사항은 별도로 구현·검증한다.
  • networkDetailAllowUrls 기본값은 빈 배열이고, networkCaptureBodies 기본값은 true다. 빈 허용 목록 때문에 현재 본문 세부 수집이 활성화됐다고 볼 수는 없다. 후속 구현에서는 본문 수집 금지 의도를 명시하고, URL·타이밍 같은 별도 메타데이터도 검사한다.

공식 참고: Replay 개인정보 설정, Replay 설정. 위 구현 분석은 lockfile로 설치한 @sentry-internal/replay@9.47.1 소스를 대리 근거로 사용했다. 앱은 Sentry.lazyLoadIntegration으로 https://browser.sentry-cdn.com/9.47.1/replay.min.js를 로드하는 경로이며, 현재 loader는 integrity 속성을 설정하지 않는다. 이번 조사에서는 Replay를 로드하지 않았으므로 실제 CDN 번들과 npm 소스의 대응·CSP·로드 실패 동작을 검증하지 않았다. 활성화 전에 실제 로드 산출물을 대조하고, 번들 포함 또는 무결성 고정 필요성을 결정해야 한다.

6. 구현과 활성화 전에 필요한 검증

  1. 좁은 구현 범위를 확정한다. 비로그인 투표 목록에서 필요한 DOM 속성·CSS 값·rrweb 이벤트의 정확한 허용 목록과 실패 시 전송 차단·복구 기준을 정한다. 이 문서는 그 전 단계의 초안이다.
  2. 합성 데이터로 수집 경계를 검사한다. 토큰 형태가 아닌 평범한 이메일·이름·임의 문자열도 속성, style, CSS 변수, URL 경로, text, metadata, 클릭 설명, resource·navigation·fetch/XHR 주소에 넣는다. snapshot·mutation·CSSOM·압축·비압축을 포함한 모든 segment와 replay_event·breadcrumb·performanceSpan에서 테스트 민감값 0건, 허용 목록 밖 필드·동적 CSS 값 0건, 미확인 정적 CSS 0건을 통과 기준으로 둔다. 필터 예외·한도 초과에서는 원문 전송 0건과 후속 손상 이벤트 차단을 확인한다. 검사 대상·입력·출력·누락 이벤트 수를 증거로 남긴다.
  3. 화면 재생을 비교한다. PC·모바일의 배너 이동, 메뉴·필터 열기, 반응형 레이아웃, 로딩·오류 상태를 원본과 비교한다. 사전에 정한 시나리오 모두에서 구조·위치·상태 변화가 유지되고, 의도한 마스킹·미디어 차단 외의 승인되지 않은 손실이 없어야 한다. 스크린샷·노드 상태 비교를 증거로 남기고, 위치·색상 등 수치 오차 허용치는 구현 전 설계에서 확정한다.
  4. 같은 화면의 상태 변화와 화면 전환을 검사한다. 로그인 상태 직접 진입, 비동기 인증 확정, 다른 탭 로그인·로그아웃, 토큰 갱신, OAuth 복귀, 광고 동의·철회를 포함한다. 허용 페이지에서 로그인·개인·결제 화면으로 이동할 때도 비허용 DOM이 녹화되기 전에 막아야 한다. SPA 이동, 뒤로 가기, BFCache, 지연 integration 로딩, error buffer·수동 start·resume까지 확인한다. 모든 비허용 상태의 기록·전송 0건과 버퍼·대기 큐 폐기를 통과 기준으로 둔다. 사후 route effect에서 stop만 호출하는 것으로 충분하다고 보지 않는다.
  5. 최종 전송과 저장 결과를 확인한다. 로컬 envelope와 Sentry 검증 환경의 모든 저장 구간을 대조해 위 민감값·비허용 필드 0건 조건을 다시 만족해야 한다. 필요한 DOM·CSS의 누락 여부와 구간 연결을 확인하고, 같은 시나리오가 Sentry 대시보드에서도 재생돼야 한다. release·Git SHA·실제 로드 SDK 산출물·검증 Replay ID를 연결해 기록한다. SDK·수집 정책·정적 CSS 빌드가 바뀌면 해당 계약 검증을 다시 수행한다. 이전 검증의 로컬 재생 성공은 대시보드 UI 확인을 대체하지 않는다.
  6. 활성화 여부를 별도로 결정한다. 독립 개인정보 리뷰와 검증이 끝난 뒤 대상·기간·샘플링·중단 조건·보관 정책을 확정한다. 현재 수집률 0을 변경하는 작업은 이 조사에 포함되지 않는다.

7. 이번 산출물과 다음 작업
