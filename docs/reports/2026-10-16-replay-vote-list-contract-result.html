4. CSS manifest

  • 빌드 ID WaMOsqHZc2V7cxWT91IY0, SDK 9.47.1. 이 빌드를 재사용했으므로 fixture를 다시 수집하지 않았다.
  • link CSS 2개: 253f05d11a58abd2.css(wire sha256 a8df5e2c…), 36f08833d15de553.css(7049b8a0…).
  • styled-jsx text 3개, class token 1,175개. 사람이 읽고 사용자 데이터처럼 보이는 token이 없음을 확인했다.
  • 생성기 절차 (리뷰 수정 뒤):
    1. link CSS는 디스크의 빌드 asset을 Chromium의 생성 CSSStyleSheet로 파싱한다.
    2. styled-jsx text는 빌드 JS의 compiled style({id, dynamic, children})에서 만든 text와 정확히 같아야 한다. 동적 style의 class는 styled-jsx 5.1.6 hash로 계산한다. 동적 인자는 literal만 허용한다.
    3. live CSSOM과 wire 값은 결과를 확인하는 데에만 쓴다.
  • 음성 시험: 제공 페이지의 link sheet와 styled-jsx sheet에 각각 insertRule로 규칙을 넣었다. 생성기는 두 경우 모두 “live CSSOM differs from build”로 종료했고 파일을 쓰지 않았다.

5. spec·계획과 다르게 구현한 점

  • styled-jsx wire 값: spec §4.2는 style을 “text 원문”으로 적었다. 실제 wire는 rrweb이 기록한 CSSOM 문자열이다(길이 727/70/542 대 원문 597/63/503). manifest는 wire와 같은 CSSOM 문자열을 저장한다.
  • styled-jsx의 신뢰 출처: 서버 HTML에는 <style>가 없다. styled-jsx는 client에서 삽입된다. 그래서 출처를 빌드 JS로 정했다. 빌드가 literal이 아닌 동적 인자를 쓰면 생성기는 실패한다.
  • 복원기 placeholder 크기: rr_width·rr_height를 inline 크기로 바꾸는 처리는 img·svg·link에만 적용한다. P0 복원 동작을 바꾸지 않기 위해서다.
  • 복원 측정: 측정 전에 유한 CSS animation을 끝낸다(§3.2).
  • 비교 selector: .vote-banner-section 대신 main section(§3.1).
  • 리뷰 범위: 리뷰어에게 계획의 ec2275f6..HEAD 대신 2bd83be4..HEAD를 주었다. 이전 P0 코드는 별도 주기에서 리뷰됐다. 리뷰어는 저장소의 모든 파일을 읽을 수 있었다.

7. 남는 위험 (spec §7)

  • 마스킹한 text의 길이·위치, class 조합, placeholder 치수는 화면 구조 정보를 남긴다. 허용한 시각 구조의 한계다.
  • bannerCount − 1 상한은 P0 설계보다 느슨하다.
  • manifest는 font mock 빌드(WaMOsqHZc2V7cxWT91IY0)에 묶인다. 실제 배포 빌드에서 그대로 쓸 수 없다.
  • SDK 내부 메모리·재시도의 한계는 P0 설계 §3과 같다.
  • fixture wire-*.bin은 원본 SDK envelope이다. 마스킹하지 않은 custom event(합성 데이터의 URL·aria-label)가 들어 있다. 저장소 밖으로 보내지 않는다.

8. 검증하지 않은 범위

  • upcoming·completed 목록, 더보기, filter, API 오류, popup (범위 A 밖).
  • 로그인 사용자, 다른 route, 실제 배포 빌드의 CSS.
  • 실제 이미지가 로드된 상태의 복원. SDK가 media를 차단하므로 복원은 placeholder만 보인다.
  • BFCache 실측 복귀와 실제 background timer 지연 (P0 미검증 항목과 같음).
