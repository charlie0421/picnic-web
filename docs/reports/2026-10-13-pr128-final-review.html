개인정보 우선 결정과 보존 제한

URL과 CSS로 모두 읽힐 수 있는 문자열의 처리에 대해 사용자 선호를 선택 질문으로 요청했다. 답변이 없는 동안 조정자는 개인정보 차단을 우선하는 작업 가정을 명시했다. 이를 사용자의 명시적 승인으로 기록하지 않는다. 원격 반영은 수행하지 않았다.

CSS로 확인되지 않은 불투명 문자열은 이스케이프된 슬래시 뒤 공백 경계 전의 #를 만나면 비운다. 따라서 .w-1/2{width:50%;color:#fff}, .w-1/2#main{color:#fff}, .w-1/2.bg-[#fff]{color:#fff} 같은 일부 CSS도 제거된다. CSS로 확인된 기존 모드(style·_cssText·rule·replace·replaceSync·isStyle)는 복합 선택자와 hex 색상을 유지한다. 공백 경계가 있는 대조군과 fragment가 없는 일부 형태도 유지한다. 모든 CSS 구문을 보존한다고 보장하지 않는다. 대표적인 영향 경로는 문맥 표식이 없는 source 0 texts[].value의 style 텍스트 변경이다. 운영 녹화에서 발생하는 빈도는 측정하지 않았다.

기존 인접 동작도 남아 있다. 슬래시 없는 callback#code=secret-opaque의 값 보존(N-1)은 F4 경로 수정 범위 밖이며 별도 검토가 필요하다. 원문·디코딩된 공백은 기존 토큰 경계 규칙을 따른다. 예를 들어 example.com\/users\/{ id }#secret-opaque처럼 공백이 있는 템플릿은 마지막 토큰에 슬래시가 없어 fragment가 남을 수 있다. 이는 새 검토의 정보 O-2이며 원문 공백을 경계로 삼은 범위의 제한이다. 이번 조합 테스트는 정한 경로 구간의 회귀 검사이며 전체 URL/CSS 문법을 검증한 것은 아니다.

여러 희소 배열에 걸친 인덱스 조회 합계의 추가 예산(R-3)은 별도 최적화 권고다. 일반 객체의 전체 키 열거, 불투명 객체의 SDK normalization 의존, 내부 참조 대상의 존재 미검사도 기존 제한이다. 대상 정보 없는 mutation·recording 간 SVG 참조·SDK 절대 URL 변환은 보존을 보장하지 않는다. blockAllMedia가 실제 SVG 내용을 차단하므로 SVG 속성 보존의 긍정 근거는 단위 테스트다.

━━ 1. 원인 ━━
opaque 모드는 fragment 를 두 장치로 막는다.

- 장치 M2: 가려진 슬래시를 플래그로 기억하고(56행) `#` 를 만나면 비운다(81행). 그러나 81행은 else 분기에 있어서 원문 `#` 만 본다.

━━ 2. 수정 기준(하나) ━━
"opaque 모드에서 `.` 또는 `#` 바로 뒤의 이스케이프 슬래시 식별자는 구간을 연다. 구간은 원문 공백 또는 원문 `{` 에서만 닫힌다. 구간이 열려 있는 동안 CSS 디코딩 결과가 `#` 인 글자가 나오면, 표기(원문·`\#`·hex)와 분기에 관계없이 '' 를 반환한다."
- 최소 구현: lib/sentry/replay-scrub.ts:56 바로 앞에 `if (opaque && escapedSelectorSlash && name.includes('#')) return '';` 를 둔다. 81·82행은 그대로 둔다. name 은 디코딩된 값이므로 `\#`·`\23 `·`\000023` 를 한 조건으로 다룬다.
- 56행 앞에 두는 이유: 구간을 여는 식별자 자신은 M1 이 실제 이름으로 검사한다(57행의 `/[?#]/` 조건). 56행 뒤에 두면 `.bg-\[\#fff\]\/50{color:red}`(J)가 '' 로 바뀐다.

- 구두점은 문자별 예외가 필요 없다. 공백과 `{` 외의 어떤 문자도 구간을 닫지 않는다. 따옴표·url()·주석 분기도 구간을 닫지 않는다.
