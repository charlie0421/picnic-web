Replay C — 운영 수집 OFF 제품 연결 설계

2026-10-18 · 기준 커밋 9645c0e6 · feat/replay-integration

사용자는 전용 워크트리에서 설계·구현·테스트를 승인했다. 실제 운영 수집 활성화는 이번 범위에 없다. PayPal과 PortOne 작업은 보류 상태를 유지한다. 이 문서는 구현과 독립 설계 검토 결과를 반영한다.

1. 목적과 완료 조건

이미 검증한 투표 목록 Replay 필터를 실제 앱의 상태와 연결한다. 운영에서는 녹화기를 불러오거나 Replay 데이터를 보내지 않는다. 합성 데이터만 제공하는 loopback 환경에서 실제 제품 연결 경로의 시작·중단·정제 결과를 확인한다.

  • 기존 샘플링 환경변수를 1로 설정해도 운영 Replay가 켜지지 않는다.
  • 인증 확인 실패·광고 동의 미확인·범위 밖 화면에서는 녹화를 시작하지 않는다.
  • 로그인·광고 삽입·화면 전환 전에 관문을 닫는다. 같은 document에서 다시 열지 않는다.
  • 정제된 Replay만 loopback 수신기에 전달한다. 일반 오류·트랜잭션 전송은 유지한다.
  • 단위·제품 브라우저 시험과 반대 공급자 리뷰의 결과를 기록한다. Sentry 저장·재생 확인을 로컬 성공으로 대신하지 않는다.

2. 범위

기존 설계의 /ko/vote, 빈 query·fragment, 인증 확인을 마친 비로그인, 명시적 광고 거절, 해당 document에서 광고 SDK 실행 이력 없음 조건을 유지한다. 진행 중 투표 목록·배너 넘김·스크롤·이미지 placeholder만 대상으로 한다. 메뉴·언어 변경·팝업·필터·더보기·새로고침·로그인·상세 화면은 시작을 막거나 즉시 종료한다.

광고 거절을 Replay 수집 동의로 간주하지 않는다. 로컬 시험 허용은 합성 시험 환경의 명시적 설정으로만 제공한다. 운영 수집 근거·동의·표본 비율·보관 기간·중지 책임자·SDK 메모리 잔존 수용 여부는 활성화 전에 별도로 결정한다.

4. 구조

  1. 안전 상태: 사용자 객체·토큰을 저장하지 않고 인증 판정, 광고 판정, 광고 실행 이력, 화면 준비 여부와 배너 개수만 유지한다. 중단 요청은 동기식이며 영구적이다.
  2. 시작 제어: 초기 unknown 상태에서는 기다린다. 모든 조건이 맞을 때 한 번만 준비한다. 준비 후 조건 변화는 기존 controller의 CLOSED로 전환한다.
  3. 앱 연결: 인증 상태 변경과 평가 시작, 광고 동의 변경과 script 삽입, 탐색 시작, 메뉴·팝업·더보기·자동 새로고침 전에 중단한다. DOM 관찰이나 React effect를 중단 경계로 사용하지 않는다.
  4. SDK 연결: 기존 Sentry client를 유지하고 공개 Replay API를 한 모듈에서 사용한다. 기본 수집률은 0/0이다. 닫힌 관문에서 stop이 발생시키는 마지막 flush도 거절한다.
  5. Worker·계약: 제품 번들에 포함되는 Worker는 vote-list manifest와 계약을 사용한다. P0 fixture Worker를 제품에 사용하지 않는다. CSS·SDK·schema 불일치 시 원문을 복구하거나 전송하지 않는다.
  6. 전송: 일반 envelope는 기존 SDK transport로 전달한다. Replay는 단일 진행 요청·세그먼트 순서·generation 확인을 거친다. 비활성 경로에서는 거절한다. 시험 endpoint는 자격 증명 없는 loopback만 허용한다.

5. 고정 제한

기존 계약의 입력·해제 후·출력 각 8 MiB, 깊이 80, 방문 값 200,000, 이벤트 10,000, 노드+tombstone 20,000을 유지한다. Worker 제한은 2초, fetch 제한은 5초, 녹화 최대 시간은 5분이다. 숨김·pagehide·뒤로 가기 복원 뒤에는 재시작하지 않는다. 폐쇄 후 새 네트워크 요청은 0회여야 한다.

현재 SDK는 9.47.1이다. 최신 문서의 stop({flush:false})는 10.67.0 이후 API이므로 사용하지 않는다. SDK 내부 비동기 작업에 남은 원본의 즉시 물리 삭제나 임의 외부 스크립트의 recorder 재시작 차단을 보장하지 않는다. SDK 업그레이드는 별도 범위다.

6. 검증

  • 실패한 인증·지연된 결과·인증 전환·동의 저장 예외·광고 실행 이력·준비 중 종료·동일 document 재시작을 검사한다.
  • 일반 오류 전송은 유지하면서, off 모드의 Replay·혼합 envelope·닫힌 이후 요청을 차단하는지 검사한다.
  • 실제 제품 빌드를 loopback 합성 upstream으로 구동한다. 1280×900과 390×900에서 배너·스크롤을 검증한다.
  • 최종 wire 데이터에서 canary, 사용자 데이터, 원문 URL·CSS URL이 남지 않는지 확인한다. manifest 불일치는 전송 0회여야 한다.
  • 운영 off 빌드와 로컬 시험 빌드를 구분한다. 전역 재시작 API와 운영 활성화 우회로를 두지 않는다. 로컬 자격 확인 API는 운영 설정에서 404를 반환한다.

설계 검토 반영

Claude Opus 5.5/high의 읽기 전용 설계 검토를 받았다. Next의 router.refresh와 팝업 응답은 별도 중단 지점으로 연결했다. 브라우저의 세션 없음만으로 HttpOnly 쿠키 부재를 확인할 수 없으므로 로컬 전용 /api/replay/eligibility가 인증·알 수 없는 Cookie와 Authorization 헤더가 없는지 추가 확인한다. 유한한 공개 언어 설정인 locale 쿠키만 허용한다. 다른 쿠키가 하나라도 있으면 로컬 시험에서도 시작하지 않는다. 이 API는 운영 설정에서 404다. 앱 인증 동작과 서버 인증 정책은 변경하지 않는다.

광고 동의 컴포넌트에 명시적 상태 신호를 추가했다. 화면 전환의 조기 capture listener와 함께 사용한다. 허용된 배너 버튼만 입력 중단 예외다. 계약 밖 팝업 응답은 SWR 상태 반영 전에 종료한다. 로컬 설정이 Vercel 빌드에 들어오면 빌드를 실패시킨다.
