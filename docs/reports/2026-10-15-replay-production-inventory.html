2. 현재 P0에서 실제로 막히는 지점

수집한 첫 Replay envelope를 기존 projectEnvelope에 오프라인으로 넣어 {ok:false, reason:'schema'}를 확인했다. 별도 진단 번들에는 실패한 검사와 현재 노드 정보만 기록하도록 메모리상의 소스를 계측했다. 원본 파일은 변경하지 않았다. 두 화면의 첫 실패는 node id 5, tag meta의 tag 허용 검사다(scripts/replay-p0/projection.ts:155). 제품 계약은 head 노드 순서나 고정 node id에 의존하지 않는다. 이 결과는 이번 production 캡처의 최초 실패를 뜻하며, 이전 dev 캡처의 최초 실패까지 소급해 확정하지 않는다.

4. 수집 경계와 미검증 범위

첫 fixture의 종료일은 2099년이었다. 이 실행에서는 SDK 주입 전에 /ko/vote RSC 재조회가 있었다. VoteListPresenter.tsx:77–91은 남은 시간을 상한 없이 setTimeout에 전달하므로 32비트 타이머 범위를 넘는 문제가 가능하다. fixture 종료일을 실행 시점 + 1일부터 시간별로 설정하고 hero 카드에 정상 이미지를 넣어 다시 수집했다. 본문의 수치는 이 최종 캡처다. 같은 production 빌드와 동일 upstream 포트를 재사용했다. 최종 두 화면에서 /ko/vote?_rsc 요청 0개와 vote-last-reload-ts=null을 확인했다. footer의 privacy/terms prefetch는 별도로 허용했다. 실제 장기 투표에 대한 타이머 상한 문제는 별도 제품 수정 후보이며 이번에 수정하지 않았다.

최종 raw 기록의 type 5에서 /_next/image 문자열은 PC 5회·모바일 9회였다. performanceSpan은 각각 8개·12개, breadcrumb와 options는 각각 1개다. 이 수치는 SDK가 캡처한 요청 시점과 수동 flush에 따른 관측이다. 기본 maskAllText/blockAllMedia만으로 custom event의 URL·selector 문자열까지 제거되지 않는 것을 확인했다.

제품 컴포넌트·라우트는 그대로 두고, 테스트 전용 ENVELOPE_TEST=1과 .next-envtest로 빌드했다. 환경은 합성 loopback Supabase 주소·가짜 키·빈 Sentry DSN/token으로 구성했다. VERCEL과 업로드 옵트인 없이 Sentry 업로드가 비활성인 경로를 사용했다. 앱이 안정된 뒤 잠긴 npm SDK를 브라우저 경계에 주입하고 raw envelope를 loopback 요청 가로채기로 수집했다. useCompression=false, minReplayDuration=0, stickySession=false, flush 지연 60초·수동 flush, tracing 비활성으로 실행했다. 따라서 3개 segment 경계는 제품의 기본 분할 정책을 검증한 값이 아니다. 기본 SDK의 text/input 마스킹과 media 차단만 적용했으며, 제품의 개인정보 제거 처리나 P0 관문은 연결하지 않았다.

각 새 브라우저 컨텍스트에서 앱 실행 전 picnic-cookie-consent=denied를 저장했다. 시작·종료 시점에 AdSense script 0개, 실행 중 외부 광고 요청 0개를 확인했다. denied 때문에 첫 방문 동의 dialog는 표시되지 않았다. 이 저장값은 광고 동의이며 현재 제품 Replay의 실행 관문이 아니다. 실제 제품 auth store와 P0 eligibility의 연결은 이번 조사 대상이 아니다. 합성 익명 화면과 denied 저장값만으로 제품 인증/동의 상태 전환이 검증됐다고 판단하지 않는다.

  • mock backend는 이번 목록용 fixture를 제공하는 단순 처리기다. 전체 PostgREST, 실제 RLS, 인증, 운영 API와 동일함을 보장하지 않는다.
  • 보상 6개는 같은 제목·thumbnail을 쓴 한 종류다. 보상 이미지 없음/오류·여러 보상·빈 제목, 배너 link, artist/group 없음·깨진 artist 이미지·후보 2명, popup을 실행하지 않았다. CDN 값이 비어 있어 CDN preconnect와 원격 이미지 경로도 빠졌다.
  • 이미지는 로컬 public 자산을 사용했다. 실제 CDN 경로·서명 URL·원격 이미지 최적화는 검증하지 않았다.
  • SDK 주입 전의 SSR streaming·초기 hydration·초기 loading 전이는 녹화하지 않았다. 스크롤 후 지연 로딩과 실패 표시는 관측했다.
  • ongoing 목록을 검증했다. upcoming/completed, 더 보기, 필터/지역/언어 변경, 모바일 메뉴 열기·닫기, API 오류·재시도는 이번 캡처 밖이다.
  • 레코드에는 type 2/3/4/5가 있었고, incremental source는 0/1/2/3이었다. CSSOM 변경 source 8/13, 다른 viewport와 브라우저, 모든 제품 상태를 일반화하지 않는다.
  • raw 기록의 URL·meta·breadcrumb·performance 데이터는 합성 조사 자료다. 특히 resource 성능 이벤트의 이미지 URL과 클릭 breadcrumb의 selector·aria-label 원문이 남는 경로를 포함한다. 제품의 beforeBreadcrumb가 Replay 내부 breadcrumb에도 적용되는지는 이번에 검증하지 않았다. 이 자료 자체가 제품 전송 허용 자료는 아니다.

5. 다음 구현 전에 정할 최소 계약

  1. 제품 CSS manifest와 그 정규화·SDK 변환 버전을 정한다. 원래 글꼴 URL은 별도 증거를 추가한다.
  2. 레이아웃 tag·head·announcer·빈 media placeholder의 구조와 삭제 후 참조 처리 규칙을 정한다.
  3. class, 상태 enum, 숫자형 style, 소수 placeholder 치수의 제한을 정한다. 배너 최대 개수와 인덱스 상한을 함께 검증한다.
  4. type 5 custom event의 기본 삭제를 유지하고, 필요한 예외가 있으면 tag/op·필드별 계약을 별도로 정한다.
  5. 새 규칙을 제품 화면의 로컬 재생으로 검증하고, 민감 문자열·허용 밖 CSS·범위 초과 값은 닫히는지 확인한다.
  6. 그 뒤 실제 제품 auth/ads/route 상태를 관문에 연결하는 별도 단계를 진행한다.

이번에는 제품 decoder를 확장하거나 운영 Replay를 켜지 않았다. 위 결정은 다음 설계·구현 범위이며 현재 승인 완료된 제품 허용 목록이 아니다.
