Replay 후속 검증: 실제 브라우저와 제품 화면

2026-10-15 KST · 기준 커밋 85a46f26d52ebc9cb2e238e25fd2e2700e643940 · Sentry SDK 9.47.1 · Chromium 153.0.8010.12 · Playwright 1.63.0 · macOS

실제 BFCache 복귀와 10초 백그라운드 전환 시험을 통과했다. 두 경로에서 P0는 닫힌 상태를 유지했다. 복귀 후 정상 제어 API를 호출해도 녹화 재시작과 새 Replay 요청이 없었고 DOM 감시자는 정리됐다.

제품 적용은 아직 준비되지 않았다. 합성 데이터로 실행한 실제 /ko/vote 화면에 P0를 그대로 연결하면 첫 flush에서 schema로 종료된다. Replay 수신 0건은 차단 동작의 관측값이며 정상 재생 성공이 아니다. 제품 코드·허용 목록·운영 설정은 변경하지 않았다.

2. 브라우저 검증 방법과 한계

이전 headless-shell에서는 BrowsingInstanceNotSwapped와 BackForwardCacheDisabledForDelegate를 관측했다. 같은 버전의 headless 전체 Chromium(channel: 'chromium')과 BFCache 비활성화 옵션 해제로 실제 캐시 복귀가 성립했다. 복귀는 새 load 이벤트가 아니므로 goBack({waitUntil:'commit'}) 뒤 persisted 복귀 상태를 확인했다. 기본 load 대기는 이미 복귀한 문서에서도 시간 초과를 일으켰다.

일반 Playwright 페이지는 포커스 강제 설정과 백그라운드 제한 해제 옵션 때문에 탭을 바꿔도 hidden이 되지 않거나 타이머 지연을 숨길 수 있었다. 별도로 실행한 전체 Chromium의 기본 컨텍스트에 connectOverCDP(..., {noDefaults:true})로 연결했다. --disable-background-timer-throttling, --disable-backgrounding-occluded-windows, --disable-renderer-backgrounding은 실행 옵션에서 제외했다. 실제 다른 탭을 전면으로 올렸고, P0의 공개 제어 API와 실제 SDK를 사용했다. SDK의 Replay 전송 시도는 1회 있었지만 닫힌 관문이 거부했다. 그 결과 send_error client report가 일반 경로로 전달됐으며, Replay fetch 0회와 구분한다.

직접 바이너리를 실행한 초기 비교에서는 타이머 지연을 관측했지만 로컬 fixture HTTP 탐색이 시간 초과됐다. 그 실패를 Replay 통과로 계산하지 않았다. 최종 시험은 Playwright의 브라우저 실행기를 사용하고, 기본 컨텍스트에 위 방식으로 다시 연결해 HTTP 탐색과 실제 숨김을 함께 확인했다. 직접 실행과 관리 실행의 HTTP 차이를 만든 개별 옵션은 확정하지 않았다.

  • 이 결과는 위 Chromium/macOS 환경의 관측이다. Firefox·Safari·모바일 OS에서는 확인하지 않았다.
  • 10초 숨김을 확인했다. 장시간 숨김, OS 절전·프로세스 강제 종료, intensive throttling 전체 조건은 확인하지 않았다.
  • Worker 2초·fetch 5초·녹화 5분의 타이머는 main event loop가 실행돼야 처리된다. 이번 관측은 벽시계 기준 즉시 종료 보장이 아니다.
  • SDK 내부 무한 processor/Worker 대기와 공개 SDK 직접 start의 한계는 이전 P0 결과대로 남는다.

3. 실제 제품 화면에서 확인한 차이

기존 워크트리의 Next dev 서버를 사용했다. 제품 소스는 수정하지 않았다. Supabase 주소와 키는 합성 loopback 서버·가짜 키로 주입했고, 운영 계정·비밀정보·운영 데이터에 접근하지 않았다. 제품 Sentry DSN은 비웠다. 글꼴은 외부 다운로드 대신 로컬 Arial 응답으로 대체했다. 따라서 next/font의 실제 font URL 형식은 이번 실행에서 관측하지 않았다. 서버 fetch는 loopback만 허용했다. 브라우저의 외부 요청은 차단했으며 Vercel analytics script 요청 1건을 관측했다.

최종 초기 화면에는 요소 307개, tag 22종, stylesheet 6개가 있었다. next-route-announcer의 shadow 자식 1개를 확인했다. 개발 전용 nextjs-portal은 별도로 구분했다. 이 수치는 최종 관측 시점의 값이다. 고정 제품 manifest의 개수로 취급하지 않는다.

P0의 tag 7개·class 4개·좁은 inline style 계약과 실제 화면 구조가 다르다. 첫 flush의 schema는 이 비호환과 일치한다. 현재 reason code만으로 최초 실패 노드나 CSS 속성까지 특정하지는 못한다. SDK가 실제 wire에서 생략하는 script 등과 DOM에 보이는 tag를 혼동하지 않는다.

필수 확인 묶음근거와 영향다음 최소 확인
head·stylesheet·shadow rootmeta/title/link와 Next announcer는 P0 계약 밖이다. 제품 CSS는 P0의 고정 CSS 한 개와 다르다. app/[lang]/layout.tsx, app/shell.ts, Next app-router-announcer.js, projection.ts:118–155.production 빌드의 실제 recorder 출력에서 tag·추가 필드·CSS 크기/hash/URL 개수를 기록한다. 글꼴 mock의 URL 제거 영향을 분리하고, 원래 빌드 자산과 대조한다. 고정 상수·placeholder·별도 schema 중 처리 방식을 결정한다.
미디어와 위치·크기SDK의 img/svg 차단 placeholder에는 isSVG와 rr_width/rr_height가 남을 수 있다. 소수 크기는 현재 정수 계약과 충돌할 수 있다. NavigationLink의 user-select, LanguageSelector의 top/left도 P0 밖이다.합성 이미지 성공/실패와 여러 viewport에서 실제 직렬화 값을 확인한다. 범위와 양자화 규칙은 검토 후 정한다.
배너·스타일 상태실제 --banner-current-index와 styled-jsx를 사용한다. 지연 슬라이드의 aspect-ratio:700/356은 승인 설계 §5의 예시 목록에도 없다. 모바일 배너 4개는 코드상 index 3에 도달할 수 있지만 이번 클릭 시험은 index 2까지다.배너 1/3/5개, 이미지 로드·지연, 390/1280px, production CSSOM을 캡처한다. 정확한 class token·CSS manifest와 필요한 값 범위를 정한다.
종료 시점과 일반 요청 연결필터가 query를 붙이면 정확한 빈 query 경로 조건을 벗어난다. 메뉴·언어 변경·로그인 모달·오류 화면은 DOM 반영 전 종료가 필요하다. 제품 tracing/loader는 P0 설정과 아직 연결되지 않았다.router.push·changeLocale·navigateWithAuth 등의 호출 순서와 요청 header를 따로 검증한다. 사후 effect 종료만으로 충분하다고 판단하지 않는다.

제품 검증의 한계: 개발 서버와 합성 배너·빈 목록만 검사했다. 실제 production CSSOM, 카드 12개·countdown·이미지·더보기·popup·loading/error·인증/동의 전환의 전체 시나리오는 미검증이다. 실제 제품 인증 상태를 P0 eligibility에 연결한 시험도 아니다. P0는 합성 eligibility로 시작했다. 위치 1px·opacity 0.01의 재생 품질 판정이나 외부 Sentry 저장·대시보드 재생을 통과했다고 주장하지 않는다.

4. 다음 작업

  1. 격리된 production build/start에서 합성 배너와 투표 카드로 실제 recorder 형태를 캡처한다. 원문을 자동으로 허용 목록에 추가하지 않는다.
  2. 관측된 head·CSS·shadow·placeholder·숫자 범위를 바탕으로 제품용 계약의 최소 변경안을 작성하고 검토한다.
  3. 계약을 구현한 뒤 정상 연속 segment와 원본 대비 재생 품질, 화면 전환 전 종료를 확인한다.

이번 작업은 검증과 조사다. 제품용 decoder 확장·운영 활성화 결정을 포함하지 않는다. Next dev가 자동 변경한 tsconfig.json과 next-env.d.ts는 정확한 변경분을 확인한 뒤 원래 내용으로 복구했고, 소유한 로컬 서버와 브라우저를 종료했다.

5. 검토와 증거

Orca의 Claude Opus 5.5/high 읽기 전용 조사자가 실제 코드와 SDK를 조사했다. 조정자가 브라우저 시험을 실행했다. 수치·결론 대조에서 심각한 사실 오류는 없었다. 글꼴 mock의 한계, 관측 개수의 출처, headless 여부, SDK의 거부된 전송 시도 설명을 보완했다. 보완 사항의 최종 대조를 완료했고, 남은 심각한 사실 오류는 없었다. 연구·사실 검증의 완료이며 제품 설계·코드·허용 목록 승인과 구분한다. 제품 적용 승인은 아니다.

검증 대상 제품·P0 코드는 기준 커밋과 같다. 전체 단위 테스트는 제품·P0 코드 변경이 없어 반복하지 않았다. 이번 새 증거는 실제 BFCache, 실제 탭 전환·타이머, 로컬 제품 호환성 시험이다. 이전 4,915개 통과를 이번 실행 수로 재사용하지 않는다.

6. 재현 자료

동일 lockfile의 의존성과 Playwright 전체 Chromium이 설치된 워크트리 루트에서 실행한다. 아래 파일은 임시 시험 디렉터리에 둔다. BFCache와 background probe는 기존 P0 실행기의 브라우저 경계만 바꾼다. 제품 probe는 로컬 서버가 실행 중일 때 사용한다. 고정 포트 53921이 사용 중이면 소유하지 않은 프로세스를 중단하지 말고 서버·probe의 포트를 함께 바꾼다. 제품 probe가 끝나면 자신이 띄운 서버만 종료하고 Next 자동 설정 변경분을 확인해 복구한다.

참고

Playwright의 noDefaults 설정은 기본 컨텍스트의 포커스 강제 설정을 적용하지 않는 옵션이다. Chrome의 timer throttling 설명은 숨김 타이머를 묶어 실행하는 동작을 설명한다. 문서의 일반 설명과 이번 환경의 실측값은 구분했다.
