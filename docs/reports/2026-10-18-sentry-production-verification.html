Sentry #73·#74 — 운영 수신 확인

2026-10-18 KST · 운영 코드 기준 main 9645c0e6 · 읽기 전용 조사

운영 Sentry에 저장된 서버 오류 2건을 확인했다. 최신 오류와 시각·경로·사건 코드가 일치하는 Vercel 401 응답 기록도 확인했다. 이전의 “확인할 서버 이벤트가 없음” 상태는 해소됐다.

#73의 민감정보 제거는 아직 확인하지 못했다. 설치된 Sentry CLI는 이벤트 목록·태그 조회를 제공하지만 상세 request·contexts를 제공하지 않는다. Orca의 Sentry 상세 탭은 로그인 화면이며 사용자 로그인을 요청했다. #73·#74 이슈는 OPEN을 유지한다.

작업의 뜻과 판정

작업쉽게 설명하면이번 결과
#73 민감정보 제거오류 보고에 쿠키·인증 헤더·쿼리·IP가 저장되지 않았는지 확인한다.검사할 운영 표본 확보. 상세 필드 검사는 로그인 대기.
#74 오류 전달서버가 보낸 오류 보고가 실제 Sentry에 도착했는지 확인한다.운영 서버 이벤트 2건 도착 확인. 특정 요청의 after() 완료 시각·flush 성공은 직접 관측하지 못했다. 모든 요청의 전달 성공을 뜻하지 않는다.

대상은 icon-casting/picnic-web이다. 두 이벤트 모두 environment=production, runtime.name=node, handled=yes, level=error다. 사건 코드는 payment.portone.webhook.signature.failed, 경로는 POST /api/payment/portone/webhook이다.

한계시각·경로·코드가 일치하는 요청을 찾았다. Sentry 상세 trace ID와 대조하지 않았으므로 같은 요청임을 확정하지 않는다. 두 기록의 31ms 차이를 전송 지연 시간으로 해석하지 않는다.

최근 23시간의 [sentry] flush 로그 검색은 0건이었다. 검색어 없는 대조 조회는 일반 요청 5건을 반환했다. 현재 코드는 flush 성공 완료 로그를 남기지 않으므로, 경고가 없는 것을 성공 증거로 사용하지 않는다.

남은 상세 검사

검사 대상현재 판정
request의 Cookie·Authorization 및 기타 인증 헤더미검증
URL query·query_string·요청 본문미검증
user.ip_address·프록시 IP 헤더·request 환경의 IP미검증
contexts·extra·breadcrumbs·tags의 민감한 값미검증
fingerprint와 사건 코드별 이슈 분리미검증. 이번 표본은 같은 코드 2건이다.

로그인 뒤 위 이벤트의 상세 필드를 읽고 존재·제거·가림 여부만 기록한다. 민감한 원문은 보고서나 Git에 저장하지 않는다. 상세 조회에 필요한 공식 API와 권한은 Sentry 개별 이벤트 조회 문서에 정의되어 있다.

CLI 인증은 기존 설정으로 확인했다. 자격 증명 파일이나 토큰 원문을 읽거나 출력하지 않았다. 운영 오류를 새로 주입하지 않았고 결제·로그인 요청·운영 설정·배포·GitHub/Jira 상태를 변경하지 않았다. PayPal·PortOne 기능 작업은 보류 상태를 유지한다. 이 보고서는 이미 발생한 PortOne 오류를 Sentry 검증 표본으로 읽은 결과다.
