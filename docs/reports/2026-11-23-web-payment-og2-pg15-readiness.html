웹 결제 운영 전환 준비

상태 · 로컬 검증 완료, 운영 적용 승인 대기. 적용 대상은 PICNIC-PROD의 PostgreSQL 15.8이다. 이 문서는 운영 명령을 승인하지 않는다.

검증한 후보

  • DB 통합 커밋 ceeeaabb32e605597166336e89a6279cdfd2717b. 웹 검증기 커밋 4bb0c2933d1148cc57306a2b7a85d62f8773e772.
  • H1 매니페스트 SHA256 5b00c2f3bc02aa324274d2cf53862c5e14f10d7bac87641dd1ff1bed2e347a8c.
  • Supabase 공개 이미지 15.8.1.038에서 운영 기준 순서와 파일명 순서로 각각 278개 파일을 적용했다. 지급 전 환불 차단과 같은 트리거가 활성화된 PORTONE 웹 지급을 확인했다. DB 리플레이에서는 기준선 덤프의 SET transaction_timeout = 0; 한 줄만 제외했다. 이 세 결과는 SQL 실행 증거다.
  • 별도 H1의 postgres:15.8에서는 main 5개, current10, M1–M5를 순서대로 설치했다. 정상 및 장애 단계가 통과했다. 장애 단계에는 같은 주문의 재시작 증명 4건이 있다. M1–M5를 DB에 설치하지 않은 스모크 실행은 PostgreSQL 카탈로그에서 보호 계약 17개가 없음을 확인하고 PostgREST 시작 전에 종료했다.
  • H1은 고정한 소스에서 결제 정의와 기존 투표 함수·타입을 가져왔다. 빈 migration 원장과 투표 RPC의 원래 owner·ACL 및 PROVIDER_WORKER 분류를 fixture에 재현했다. 투표 실행과 운영 원장에 이미 기록된 분기는 검증 범위에 포함되지 않았다.
  • 전체 DB 리플레이는 파일별 트랜잭션을 사용했다. H1은 선행 main 5개만 파일별 트랜잭션으로 감싸고, 기존 15개는 psql 기본 동작으로 실행했다. H1은 합성 PayPal과 로컬 PostgREST 검증이다. 실제 provider, 운영 gateway, 운영 DB 쓰기는 검증하지 않았다.

승인 전 사전 점검

  1. 운영 담당자가 승인 식별자, 작업 창, W·D 배포 커밋, 증거 보관 위치를 기록한다.
  2. 운영 migration 원장에서 H1의 선행 main 5개가 이미 적용됐는지 확인한다. 버전과 SQL SHA256을 매니페스트와 대조한다. 아래 미적용 15개가 모두 없고 원장이 검증 당시보다 앞서지 않았는지 확인한다. 차이가 있으면 적용 계획을 다시 검토한다.
  3. 웹 결제 전용 등록·청구 진입을 닫는다. 배포 전과 current10 직후에 새 웹 주문과 청구가 허용되지 않는지 확인한다.
  4. 웹 verification·settlement의 기존 스케줄, 진행 중 요청, 활성 lease 및 DB 트랜잭션을 조회한다. 재시도·자동 재시작·외부 스케줄러도 대조한다. 실행 상태가 불명확하면 적용을 시작하지 않는다.
  5. 공용 wallet-operation-worker가 처리하는 모바일 구매와 환불을 보존한다. 웹 진입과 웹 작업의 종료를 별도로 증명한다. 공용 스케줄 중단이 필요한 경우에는 영향 범위와 복구 조건을 별도로 승인받는다.

승인 후 적용 방법

  1. 운영 원장에 이미 있는 main 마이그레이션 5개는 설치 자료와 대조한다. 이번 적용 대상은 아래 15개다.
  2. 이전 버전이 최신 운영 원장보다 앞선다. 기존 운영 정책에 따라 일괄 --include-all을 사용하지 않고, 아래 파일만 허용하는 적용 키트를 검토한다. 운영 적용 전에 키트의 실제 전송 SQL과 원장 기록을 같은 입력으로 재검증한다.
  3. 각 파일을 검토된 트랜잭션으로 적용한다. 성공한 버전, 이름, 원본 SQL을 원장 기록과 대조한다. 실행 결과가 불명확하면 원장과 카탈로그를 확인한 뒤 다음 파일로 이동한다.
  4. current10 뒤 M1–M5를 순서대로 적용한다. 이 구간에서 웹 소비자를 시작하지 않는다. 일부 파일만 성공했으면 진입 차단을 유지하고 확인된 적용 내역을 보존한다.
  5. 실제 카탈로그에서 서비스 RPC 분류, 실행 권한, private 함수 접근 제한, RLS, 불변 증거 보호를 대조한다. assert_wallet_service_rpc_manifest(), S8의 claim·버전 검사, M4 적용 뒤의 상태 점검과 경보를 확인한다. M4가 바꾼 heartbeat 함수의 지문과 checker를 별도 검토한다.
  6. 운영 승인 범위에서 호환 W·D 소비자를 배포한다. 지급 전 환불 보호를 포함한 작업자 커밋을 대조한다. 웹 재조정 cron과 secret, provider credential, PayPal COMPLETE는 각각 해당 승인 조건을 확인한 뒤에만 연다.
