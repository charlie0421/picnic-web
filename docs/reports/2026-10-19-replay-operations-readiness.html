보관·삭제 해석의 범위

현재 계정 API의 개별 Replay 보관 필드는 null이다. 이 값을 0일로 해석하지 않았다. 실제 Team 구독과 기본 90일 값, Sentry의 데이터 유형별 보관 표를 함께 대조해 현재 요금제로 새로 수집할 Replay의 90일 보관을 확인했다. 공식 문서는 수집 시점의 요금제가 보관 기간을 정하며 기존 데이터에는 원래 기간이 유지된다고 설명한다. 기존 녹화의 실제 만료나 백업 삭제 완료를 시험한 결과는 아니다.

개별 Replay 삭제 API는 프로젝트와 진단 번호로 녹화를 지정한다. 현재 계정의 권한 확인과 실제 삭제 성공은 구분한다. 최초 설계는 조사 종료 다음 영업일·수집 후 7일 이내 수동 삭제를 목표로 했다. 이후 사용자는 90일 자동 보관을 허용했고 기존 안내의 7일 수동 삭제 약속을 제거했다. 즉시 백업 제거를 약속하지 않는다.

기존 OFF 절차의 확인 지점

  1. 담당자가 운영 서버 스위치 REPLAY_DIAGNOSTIC_ENABLED를 OFF로 설정한 배포를 준비한다.
  2. 해당 Vercel 배포가 실제 운영 도메인에 반영됐는지 확인한다.
  3. 운영 허용 API가 404를 반환하고 새 문서에 진단 진입 버튼이 나타나지 않는지 확인한다.
  4. 이미 열린 합성 시험 문서가 다음 자격 검사에서 종료되고 추가 전송하지 않는지 확인한다.
  5. 이미 저장된 녹화의 삭제는 별도 절차로 처리한다.

위 목록은 승인된 설계와 현재 코드를 대조한 확인 지점이다. 이번 점검은 이 배포 절차를 실행하지 않았다. OFF 배포가 반영되기 전과 이미 허용 응답을 받은 진행 요청까지 변경 요청 순간에 차단한다고 보장하지 않는다.
