Replay 운영 준비 읽기 전용 점검

점검일: 2026-10-19 16:45~16:53 KST · 애플리케이션 코드 eeb9f802 · 문서 기준 fa2575e6 · 현재 핸드오프

점검 완료, 운영 활성화 조건은 미충족이다. 현재 요금제의 Replay 자동 보관은 90일이며, 현재 담당자 계정의 열람·삭제 권한을 확인했다. 삭제 요청 주소, 개인정보 고지와 저장 지역의 정합성, 계정 측 결제 후속 확인이 남아 있다. 새 구현의 실제 저장·재생·삭제와 OFF 배포 검증도 아직 수행하지 않았다. 운영 Replay는 OFF이고 PR #144는 병합·배포 전이다.

확인 결과

항목이번 확인남은 조건
자동 보관로그인한 계정의 Team 요금제와 planDetails.retentionDays=90을 확인했다. 공식 표의 Team Session Replays도 90일이다.운영 동의 안내에 확인한 90일을 사용한다. 합성 시험의 30일은 시험값이다. 수집 후 최대 7일 이내 수동 삭제 목표와 구분한다.
열람 권한프로젝트는 비공개이며, 조직·프로젝트 팀의 전체 회원 조회에서 현재 담당자 소유자 계정만 확인했다. 다음 페이지가 없음을 확인했다.현재 인원 범위에서는 담당자 제한을 충족한다. Replay 개별 접근 제한은 켜져 있지 않으므로 멤버·팀 구성 변경 시 범위를 재확인한다.
삭제 권한현재 계정의 project:admin·project:write 권한을 확인했다. 공식 개별 Replay 삭제 API의 요구 권한과 일치한다.삭제 요청은 실행하지 않았다. 새 구현의 합성 Replay를 삭제한 뒤 조회 불가 여부를 확인하는 실제 시험이 남아 있다.
삭제 요청 주소https://www.picnic.fan/support와 /contact는 각각 영어 경로로 이동한 뒤 404였다. /ko/faq는 200이지만 요청 접수 경로로 확인하지 못했다.담당자가 실제 접수 가능한 HTTPS 주소를 확정해야 한다. 코드의 cs@picnic.fan은 수신·처리 여부를 검증하지 않았다. 문의를 전송하지 않았다.
고지와 저장 지역운영 /ko/privacy는 200이다. 읽은 본문에는 Sentry·Replay·화면 진단 설명이 없었다. 제6조는 모든 개인정보의 저장 지역을 대한민국으로 설명하지만 Sentry 조직 설정의 저장 지역은 미국이다.현재 고지와 실제 전송·저장 조건을 맞춰야 한다. 이 결과는 기술적 내용 대조이며 법률 적합성 판정이 아니다. 개인정보처리방침은 변경하지 않았다.
사용량·과금현재 요금제, 조직 전체 Replay 사용량, 추가 과금과 공유 예산 한도를 조회했다. 결제 정보 후속 확인이 필요한 상태다.담당자가 계정 결제 상태를 정리한 뒤 다시 확인한다. 청구 금액·결제 수단·주소·계정 원문은 공개 Git 문서에 넣지 않았다. 상세 근거는 비공개 로컬 기록에 보관한다.
중지 절차운영 허용 API /api/replay/eligibility?mode=diagnostic의 익명 GET은 404였다. 구현은 서버 스위치가 1이 아니거나 고지·빌드 검증이 없으면 닫힌다.현재 404는 새 기능의 OFF 배포 리허설을 대신하지 않는다. 실제 Vercel 배포 반영과 열린 문서의 추가 전송 중단은 별도 검증이 필요하다.

보관·삭제 해석의 범위

현재 계정 API의 개별 Replay 보관 필드는 null이다. 이 값을 0일로 해석하지 않았다. 실제 Team 구독과 기본 90일 값, Sentry의 데이터 유형별 보관 표를 함께 대조해 현재 요금제로 새로 수집할 Replay의 90일 보관을 확인했다. 공식 문서는 수집 시점의 요금제가 보관 기간을 정하며 기존 데이터에는 원래 기간이 유지된다고 설명한다. 기존 녹화의 실제 만료나 백업 삭제 완료를 시험한 결과는 아니다.

개별 Replay 삭제 API는 프로젝트와 진단 번호로 녹화를 지정한다. 현재 계정의 권한 확인과 실제 삭제 성공은 구분한다. 승인된 설계의 조사 종료 다음 영업일, 늦어도 수집 후 7일 이내 수동 삭제 목표를 유지한다. 즉시 백업 제거를 약속하지 않는다.

기존 OFF 절차의 확인 지점

  1. 담당자가 운영 서버 스위치 REPLAY_DIAGNOSTIC_ENABLED를 OFF로 설정한 배포를 준비한다.
  2. 해당 Vercel 배포가 실제 운영 도메인에 반영됐는지 확인한다.
  3. 운영 허용 API가 404를 반환하고 새 문서에 진단 진입 버튼이 나타나지 않는지 확인한다.
  4. 이미 열린 합성 시험 문서가 다음 자격 검사에서 종료되고 추가 전송하지 않는지 확인한다.
  5. 이미 저장된 녹화의 삭제는 별도 절차로 처리한다.

위 목록은 승인된 설계와 현재 코드를 대조한 확인 지점이다. 이번 점검은 이 배포 절차를 실행하지 않았다. OFF 배포가 반영되기 전과 이미 허용 응답을 받은 진행 요청까지 변경 요청 순간에 차단한다고 보장하지 않는다.
