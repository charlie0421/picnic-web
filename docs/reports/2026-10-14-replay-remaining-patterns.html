Replay 예외 패턴 보완 및 검증

2026-10-14 · 기준 main 884dcbf6 · fix/replay-remaining-patterns

기존 보고서의 6개 예외와 브라우저가 변환한 주소를 보완했다. 검증용 녹화에서 민감값을 제거하고 정상 CSS를 보존했다. 자동 수집은 활성화하지 않았다. 아래 한계는 여전히 적용된다.

수정 범위

예외처리
공백이 포함된 { id } 주소일반 문자열의 괄호 안 공백을 주소의 끝으로 간주하지 않는다.
CSS custom property의 code\=...선언 구간에서 이스케이프된 대입 문자를 검사한다. 선택자 구간의 해석 결과는 버린다.
href의 CSS 이스케이프원문과 브라우저가 역슬래시·공백을 변환한 주소를 검사한다. 탭·줄바꿈·폼피드·6자리 및 생략된 종결자도 확인했다.
일반 문자열의 \u003dUnicode·hex 표기를 검사 전용 값으로 해석한다. 해석한 값을 전송하지 않는다.
이스케이프된 주소의 [ id ]중괄호·대괄호·소괄호 안 공백을 처리한다.
분리된 이스케이프 키검사용 키를 원래 길이로 해석한다. 기존 검사도 함께 유지한다.

변경은 Replay 전용 필터와 테스트에 한정했다. 공용 서버 필터, 의존성, 샘플링 기본값은 변경하지 않았다. 해석이 위험한 필드는 전체를 비우므로 일부 화면 정보가 사라질 수 있다.

검증 결과

검사결과
수정 전 실패 재현초기 28개, URL 정규화 24개, 리뷰 반례 28개와 중첩 블록 8개가 각각 수정 전에 실패했다.

전체 테스트213개 파일, 4,776개 통과. 기존 예상 실패 6개와 건너뛴 검사 1개.
타입·린트npx tsc --noEmit --incremental false, npm run lint 통과.
실제 브라우저Chromium과 실제 Sentry SDK 9.47.1의 압축 Replay 전송을 검사했다. 10개 DOM 추가와 10개 변경 값이 모두 비워졌다. 정상 선택자 4개와 앱 CSS 100,546바이트가 보존됐다.
독립 리뷰재검증 진행 중.

브라우저 테스트는 로컬 production 빌드의 격리된 fixture에서 실행했다. 초기 fixture의 TypeScript 반복문 오류를 수정했고, 임시 라우트와 충돌한 전체 테스트는 fixture 정리 후 순서대로 다시 실행했다.

Sentry 서버 저장 검증

최종 코드로 생성한 검증용 Replay를 icon-casting / picnic-web의 replay-verification 환경에 저장했다. 로컬 수신기로 캡처한 필터 적용 녹화를 같은 내용으로 다시 압축해 전송했다. 운영 사용자 세션이나 운영 설정은 변경하지 않았다.

검증용 Sentry Replay 열기 · 확인 시각: 2026-10-14 17:15 KST.

  • 공식 API에서 녹화 33개 이벤트를 다시 받았다. 테스트 민감값은 없었다.

  • 저장된 DOM 이벤트(type 4/2/3)를 로컬 rrweb으로 재생했다. 입력 마스킹, 10개 빈 속성, 정상 색상과 스타일을 확인했다. SDK 전용 custom event는 재생 검사에서 제외했다. Sentry 대시보드의 재생 UI는 직접 확인하지 않았다.

API 참고: 녹화 구간 조회, Replay 조회.

남은 한계와 운영 판단

  • 임의 CSS custom property에 들어간 템플릿 주소(--cb: example.com/users/{ id }#... 및 이스케이프된 슬래시 변형)는 아직 남을 수 있다. 로컬 입력으로 재현했다.
  • 일반 슬래시 경로 뒤에 이스케이프된 fragment만 있는 주소는 브라우저 정규화 후 정상 경로와 구별하기 어렵다. 앞선 escaped-slash 흔적이 없는 이 형태도 로컬 입력으로 재현했다.
  • 정규화된 주소 감지는 휴리스틱이다. 같은 문자 패턴의 정상 주소도 지울 수 있다. 일반 문자열의 괄호·슬래시·fragment 조합도 값 전체가 비워질 수 있다.
  • 이 결과는 정해진 URL·토큰 패턴의 검증이다. 임의 문자열의 모든 개인정보를 제거한다는 보장은 아니다. 자동 수집을 켜려면 수집 필드와 CSS 허용 범위를 먼저 정하고, 그 기준으로 별도 검증해야 한다.

이 보고서는 앞선 fragment 경계 보고서의 6개 잔여 사례에 대한 후속 결과다. 운영 자동 Replay 수집은 기존 비활성 상태를 유지한다.
