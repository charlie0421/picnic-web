Replay P0 로컬 검증 결과

2026-10-14 · Sentry JavaScript SDK 9.47.1 · 합성 데이터 · loopback 수신기

로컬 P0의 정상 기록, 종료 후 전송 차단, 유한 오류 정리 시험을 통과했다. 실제 SDK가 기록한 3개 연속 구간을 수신하고 별도 DOM 복원기로 비교했다. 제품 연결이나 운영 활성화는 수행하지 않았다.

수정한 문제

첫 기록 중 종료되면 SDK의 start 호출이 반환하기 전에 stop이 실행돼 DOM 감시자가 남았다. controller는 전송 관문과 소유 작업을 즉시 닫고, 같은 start 호출이 끝난 직후 공개 stop을 실행하도록 수정했다. 단위 실패 시험과 실제 SDK 재현에서 수정 후 감시자 정리를 확인했다. Playwright 자체 감시자는 도구의 InjectedScript stack으로 별도 제외한다.

기존 span의 frozen DSC는 createDsc hook 전에 반환된다. 활성 trace propagation target을 둔 대조군에서 요청 baggage에 Replay ID가 남았다. 승인 설계 §3에 따라 P0의 tracePropagationTargets=[]를 적용했다. 새/기존 span의 녹화 중·종료 후 요청 헤더에서 Replay ID가 없고, 일반 오류·transaction 전달은 유지된다. 제품에서 헤더 전파를 다시 켜려면 별도 설계·검증이 필요하다.

시간 표는 22개 케이스의 전체 실행 관측값이다. 정상 기록 2개 케이스는 승인된 합산 노드 예산으로 재확인했으며, 그 재확인의 시간은 별도 측정하지 않았다.

CSS 음성 시험의 첫 주입은 주석이어서 SDK 정규화가 제거했다. 실제 미승인 CSS 규칙으로 수정한 뒤 종료를 확인했다. 해당 실패와 재검증 이력은 구조화 결과에 보존했다. fake clock에서 SDK가 새 iframe으로 얻는 native timer는 시험용 DOM 경계에서 같은 clock으로 연결했다. 별도 실제 시간 시험으로 재시도 간격을 대조했다.

미검증과 한계

  • Chromium의 실제 BFCache 복귀는 BrowsingInstanceNotSwapped / BackForwardCacheDisabledForDelegate로 성립하지 않았다. 모의 pagehide/pageshow 경로만으로 BFCache 통과를 주장하지 않는다. 실제 이동의 pagehide·hidden 시 CLOSED 상태는 관측했다.
  • 실제 background timer throttling의 지연은 측정하지 않았다. 2초·5초·5분 제한은 main event loop가 실행될 때 적용되며 벽시계 기준 즉시 종료를 보장하지 않는다.
  • SDK 내부 무한 대기와 전역 직접 start 호출의 한계는 남아 있다. 메모리의 물리적 삭제·모든 SDK 자원 해제를 보장하지 않는다.
  • SDK 스크립트를 제외한 독립 정적 fixture만 검증했다. Next head·route announcer·shadow root·제품 CSSOM·로그인·광고·실제 API·제품 beforeSend의 전체 분기·외부 Sentry 저장은 범위 밖이다.

독립 리뷰

지적처리와 검증
M1 · 일반 성능 이벤트 연결standalone span.data와 transaction.spans[].data의 replay_id/replayId를 제거한다. 실제 클릭의 INP 성능 지표는 유지한다. 실제 이동만 한 첫 시험에서는 누락이 재현되지 않았으나, window capture가 먼저 실행되는 visibility 주입에서 실제 SDK의 연결 누락을 재현했다. 수정 후 두 경로 모두 PASS다.
M2 · 실제 클릭 형식DOM click() 시험을 Playwright page.click으로 바꾸고 실제 wire fixture를 갱신했다. pointerType 0…2와 좌표 없는 focus/blur 형식을 검증하며, 별도 복원기의 버튼 초점 상태도 비교한다. 수정 전 실제 클릭은 1구간 뒤 종료됐고 수정 후 3구간이 전달된다.
L1 · 삭제 기록 예산승인 설계 §6와 계획의 한도는 노드와 tombstone 기록의 합계다. 삭제 노드의 형식 정보를 재삽입 검사에 보관하므로 두 저장소를 합산한다. 한도를 고유 ID 수로 바꾸지 않았다. 19,997개 노드+3개 삭제 ID는 허용하고 19,998+3은 거부하는 경계 시험과 코드 설명을 추가했다.
L2 · 누락된 시험fixture의 style과 검토한 raw/normalized CSS·각 SHA-256을 대조한다. 허용되지 않은 class canary만 제거하고 card token을 보존하는 시험을 추가했다.
결과 판정기필수 한계 3개 외에 추가된 한계가 미관측이어도 실패 코드가 되도록 보완했다. RED 1개 실패 뒤 GREEN 8개 통과.

8 MiB 출력 경계 시험은 큰 투영을 네 번 실행한다. 병렬 전체 시험에서 기본 5초 제한을 초과해 이 크기 시험의 한도만 15초로 조정했다. 실제 Worker 2초 제한은 유지했으며 별도 시험으로 확인했다.
