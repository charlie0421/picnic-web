PICNIC-3014 사이트맵 조회 개선

사용자가 10/29 승인한 수정이다. 기존 사이트맵은 ID와 날짜만 사용하지만 getVotes('all')로 후보·아티스트·보상까지 읽었다. 운영 조회 오류의 원인 후보이며, 이번 수정으로 당시 오류의 발생 경로가 확정되는 것은 아니다.

설계와 범위

사이트맵 전용 서비스가 공개 클라이언트로 id,updated_at,created_at만 읽는다. 삭제 제외와 visible_at ≤ 조회 시작 시각 조건을 유지한다. 예정·진행·종료 투표 모두 포함한다. ID 오름차순으로 최대 500개씩 읽고 마지막 ID 뒤에서 계속한다. 서버가 더 작은 행 제한을 적용해도 빈 페이지를 받을 때까지 조회한다.

공통 목록 조회를 변경하면 화면용 후보 데이터에 영향을 주므로 전용 서비스를 선택했다. 단일 무제한 조회는 서버 행 제한으로 URL을 누락할 수 있어 사용하지 않는다. 페이지 중간에 실패하면 불완전한 투표 목록을 반환하지 않고 기존 사이트맵 오류 처리에 전달한다. 캐시·인증·DB 정책·화면 조회는 이 수정의 범위가 아니다.

구현 계획

  1. 실제 사이트맵 생성과 Supabase 쿼리 빌더를 실행하는 테스트를 작성한다. 외부 HTTP만 가짜 응답으로 대체한다.
  2. 불필요한 관계 조회와 서버 행 제한 뒤 URL 누락을 수정 전 실패로 확인한다.
  3. lib/data-fetching/server/vote-sitemap-service.ts를 추가하고 app/[lang]/sitemap.ts에서 사용한다.
  4. 공개 범위, 날짜 대체값, 중복·누락, 빈 결과, 페이지 오류를 검증하고 전체 테스트와 TypeScript 검사를 실행한다.
  5. 다른 공급자의 독립 리뷰를 받고 결과와 남은 제한을 기록한다.

회귀 검증은 __tests__/sitemap-votes.test.ts에 둔다. 검토 초점은 서버 행 제한이 요청 크기보다 작은 경우, 페이지 사이의 시각 변화, 삭제·비공개 투표, 날짜 대체값, 중간 페이지 실패다.

검증 결과

  • 기존 관련 테스트: 19개 통과.
  • 신규 테스트: 수정 전 불필요한 관계 조회·서버 행 제한 뒤 누락·후속 페이지 오류 처리의 세 검사가 실패했다. 수정 후 4개 모두 통과했다.
  • 전체 npm test: 262개 파일, 5,465개 통과, 기존 예상 실패 2개·건너뜀 1개. 종료 코드 0.
  • npx tsc --noEmit --incremental false: 종료 코드 0, 오류 출력 없음.

운영 DB에서도 읽기 전용 트랜잭션과 anon 역할로 동등한 첫 페이지 SELECT를 실행했다. EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON) 결과는 공개 투표 260개, vote_pkey Index Scan, 실행 0.408 ms·계획 1.022 ms였다. DB 데이터와 설정을 변경하지 않았다. 이는 단일 시점의 DB 검사이며 HTTP 전체 지연이나 마감 부하 성능을 보장하지 않는다.

Claude Sonnet 5 / medium의 독립 읽기 전용 리뷰가 완료됐다. 차단 이슈와 수정 요구는 없었다. Dispatch ctx_39958c881177의 worker_done/succeeded가 10/29 16:29:49 KST에 수락됐다. 페이지 조회는 여러 번 왕복할 수 있지만, 서버 행 제한 뒤의 누락을 막기 위해 필요한 동작이다. 운영 웹 배포 전이다.
