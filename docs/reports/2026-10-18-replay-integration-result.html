2026-10-18 · 브랜치 feat/replay-integration · 기준 9645c0e6

운영 Replay는 OFF다. 실제 제품 코드에 수집 제어와 정제 전송을 연결하고, 합성 데이터만 사용하는 로컬 시험으로 검증했다. 독립 리뷰에서 발견한 추적 헤더 순서 문제를 수정했다. 독립 재검증에서 지적 3건 모두 해결됐으며 운영 OFF 상태의 연결을 승인받았다.

Replay에서 바뀐 동작

  • 기존 환경변수의 샘플링 값이 양수여도 운영 녹화가 켜지지 않는다. 수동 Replay envelope도 비활성 전송 관문에서 거절한다.
  • 로컬 전용 설정·정확한 loopback 주소·합성 Supabase가 모두 맞을 때만 연결된다. Vercel 환경에서 로컬 플래그를 켜면 빌드가 실패한다.
  • 인증 오류·시간 초과는 비로그인으로 간주하지 않는다. 서버는 HttpOnly를 포함한 인증·알 수 없는 쿠키를 거절하며 유한한 공개 언어 설정만 허용한다.
  • 광고 거절을 Replay 동의로 간주하지 않는다. 로컬 합성 시험만 명시적으로 허용한다.
  • 로그인·광고 삽입·라우팅·팝업·더보기·자동 갱신 전에 중단한다. 중단된 document에서는 다시 시작하지 않는다.
  • Worker는 기존 vote-list 계약으로 새 envelope를 만든다. 계약·순서·예산에 맞지 않으면 원문을 보내지 않는다. 일반 오류·트랜잭션 전송은 유지하고 Replay 연결값을 제거한다.

close-*는 첫 구간을 받은 뒤 해당 동작을 수행했다. 이후 새 Replay 요청은 0회였다. 이전 실패는 언어 쿠키의 과도한 차단 1건과 시험 도구의 복원 DOM 정리·메뉴 선택자·합성 JWT 인코딩 문제였으며 각각 수정 후 재검증했다.

독립 리뷰 수정 내역

  • 추적 헤더: SDK가 Replay ID를 추가한 뒤 제거 훅이 실행되도록 등록 순서를 고쳤다. 실제 SDK로 재현한 회귀 시험과 브라우저 요청 헤더 검사를 추가했다.
  • 시작 자격: 잘못된 JSON·추가 필드·시간 초과·확인 중 종료·생성자 예외에서 시작하지 않는 시험을 추가했다.
  • 중단 알림: 한 구독자가 예외를 던져도 앞서 호출된 구독자가 즉시 중단 상태를 받도록 보강했다.

Sentry 다음 순서

#73 최신 상태와 #74 최신 상태를 다시 확인했다. 두 작업의 코드 수정은 이미 끝났고 이슈는 OPEN이다. 운영 Sentry에 저장된 서버 이벤트 한 건에서 도착 여부와 쿠키·인증 헤더·쿼리·IP가 없는지를 확인해야 한다. 현재 세션에는 Sentry 조회 도구가 없고 플러그인 검색 결과도 없다. 커넥터 재인증을 요청했으며 운영 확인과 이슈 종료는 하지 않았다.

운영 활성화 전에 남은 일

수집 근거와 동의, 표본 비율, 보관 기간, 중지 책임자, SDK 내부 잔존 데이터 수용 여부를 결정해야 한다. 운영 origin과 배포별 manifest를 검증하고 Sentry 저장·재생을 확인해야 한다. 현재는 Chromium 두 viewport만 확인했다. 실제 모바일 브라우저의 주소창 변화가 resize를 발생시키면 보수적으로 종료할 수 있어 실기기 확인이 남아 있다. SDK 내부 원본의 즉시 물리 삭제, 임의 외부 스크립트의 recorder 재시작 차단, 실행 도중 서버가 새로 설정한 HttpOnly 쿠키를 브라우저에서 즉시 감지하는 것은 보장하지 않는다.
