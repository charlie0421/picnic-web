동의와 기존 안전 상태

signals.ts의 closed는 문서 수명 동안 단방향으로 유지한다. 인증·광고·경로 변경 신호는 페이지 로드부터 유지한다. 현재 browser-transport.ts의 초기 클릭·키·입력 감시 설치를 운영 흐름에 그대로 복사하지 않는다. 운영 흐름에서는 동의 시작 click 핸들러 안에서 상호작용 종료 감시를 설치한다. 진입 버튼·안내 열기·취소 동작은 시작 시도를 소비하거나 문서를 닫지 않는다. 녹화 시작 이후에는 기존의 엄격한 입력 종료 규칙을 적용한다.

동의가 없으면 runtime.prepare()를 호출하지 않는다. recorder를 불러오기 전에 종료 감시를 설치하고, 동의 UI 제거·페이지 준비·최종 자격 확인을 마친 뒤 시작한다. SDK 시작 후 진단 번호를 표시하기 전에는 전송 문을 열지 않는다. 번호 표시 전에 첫 envelope가 도착하면 대기하거나 재시도하지 않고 세션을 닫는다. 고정 제어 UI와 번호 텍스트의 초기 표시·변경을 계약에 명시하고, Replay 출력의 번호 텍스트도 마스킹한다.

광고 동의 변경이 이미 문서를 닫았다면 새로고침 후 다시 안내를 열도록 한다. 로그인·광고 허용·실패를 지우기 위해 신호나 singleton을 교체하지 않는다. 중지 버튼은 capture 단계에서 전송 문을 닫으며 키보드 동작도 같은 순서를 따른다.

전송 전 검사

기존 createP0Transport의 loopback 제한은 유지한다. 운영용 transport를 별도로 두고 검증된 변환·마지막 상태 검사·취소 절차를 공유한다. 운영 transport는 고정한 Sentry 프로젝트의 HTTPS ingest 주소 한 곳만 허용한다. 페이지 값·query·저장소에서 전송 주소를 받지 않는다. redirect·credentials·referrer·keepalive는 기존 제한을 유지한다.

운영 ingest 인증은 배포 구성의 공개 DSN에서 만든 고정 sentry_key 쿼리와 sentry_version=7을 사용한다. DSN의 host·project ID·공개 키를 검증하고 다른 쿼리를 허용하지 않는다. loopback transport의 query 금지 규칙은 바꾸지 않는다. 합성 envelope로 CORS와 수락 여부를 검증한다.

서버 자격 검사에는 운영 허용 스위치를 추가한다. 기본값은 OFF다. 시작 전과 각 envelope 전송 직전 같은 출처의 no-store 요청으로 운영 허용 여부와 익명 쿠키 조건을 확인한다. 응답 제한은 1초다. 응답 직후 로컬 자격·동의·세대·60초 제한을 다시 확인하고 같은 실행 흐름에서 전송한다. 검사 중 중지되면 검사와 전송 대기를 취소한다. 실패·알 수 없는 응답·허용 해제는 세션을 닫는다.

서버 검사는 빈 쿠키 또는 허용한 locale 쿠키 한 개만 인정한다. 알려지지 않은 쿠키와 Authorization 헤더는 거부한다. 새로운 동의 쿠키를 허용 목록에 추가하지 않는다. 검사 응답과 전송 사이의 서버 상태 변경, 다른 응답이 늦게 설정한 HttpOnly 쿠키까지 원자적으로 막는 구조는 아니다. 클라이언트 직접 전송에는 이 한계가 있다.

화면 변환과 메타데이터

검증된 allowlist 방식으로 데이터를 새로 구성한다. 허용하지 않은 CSS·DOM 변경은 원본을 보내는 대신 종료한다. 운영 release는 배포 커밋, environment는 고정 진단 환경명으로 제한한다. URL은 기존 고정 가상 경로를 유지하고 실제 주소를 넣지 않는다. 기술 메타데이터 변경과 진단 제어 UI는 manifest·계약 테스트에 반영한다.

각 배포에서 최종 빌드 산출물을 기준으로 manifest를 생성·대조한다. 다시 빌드했다면 최종 산출물로 다시 대조한다. CSS 해시·스타일 정의·SDK 버전·release·environment 일치가 확인된 manifest와 검증 표식을 함께 배포한다. 불일치하면 배포 검사를 실패시키며, 서버가 현재 배포의 검증 표식을 확인하지 못하면 진단 진입 UI도 OFF로 둔다. Chrome 안정판이 바뀌면 첫 segment 통과와 연속 재생을 검증한다. 미검증 CSS 표현을 자동 허용하지 않는다.

최초 변환 전에 원본 recorder 데이터가 브라우저 메모리와 변환 worker에 존재할 수 있다. 원본을 로그·별도 저장소·네트워크로 보내지 않는다. 60초와 8 MiB 한도는 전송 직전에도 검사한다. worker 2초, 전송 5초 제한과 단일 진행 요청을 유지한다. 오류나 시간 초과 후 재시도하지 않는다.

8 MiB는 직렬화된 변환 결과 전체의 바이트 수를 fetch 호출 직전에 누적한다. 실패·취소·시간 초과에도 차감하지 않는다. 전송 5초 제한은 실제 POST부터 측정하며, 앞선 worker 2초와 서버 자격 검사 1초를 포함하지 않는다. 어느 단계든 60초 세션 만료와 중지는 우선한다.

오류와 진단 번호

일반 Sentry 오류 수집은 계속 독립적으로 동작한다. 이번 단계에서는 오류 이벤트에 Replay ID를 붙이지 않는다. 진단 번호는 SDK의 replay_id이며 별도 대응표를 만들지 않는다. 진단 번호를 접수할 검증된 문의 경로는 아직 없다. 경로를 확인한 뒤에만 사용자에게 안내한다. 번호는 해당 녹화를 찾는 식별자이므로 공개 게시를 권하지 않으며, 사용자 이름이나 계정 ID와 자동 결합하지 않는다. 자동 오류 연결은 별도 범위다.

5. 중지·보관·삭제의 실제 의미

상황구현·검증 후 보장할 동작남는 한계
사용자가 중지동기적으로 전송 상태를 CLOSED로 만들고 대기 작업을 취소한 뒤 SDK stop을 호출한다. stop이 flush를 호출해도 새 전송은 거부한다.이미 Sentry에 도착한 기록은 삭제되지 않는다. 마지막 버퍼가 빠져 녹화 끝부분이 짧을 수 있다.
60초 경과타이머와 전송 직전 시간 비교로 종료한다. 시계 역행·시간 값 이상도 종료한다. 시간 측정에는 단조 증가 시계를 사용한다.브라우저가 멈춘 동안 SDK 내부 정리가 지연될 수 있다. 재개 후 추가 전송은 막는다.
운영 중지 스위치 OFFOFF를 제공하는 서버 배포가 실제 활성화된 뒤 다음 자격 검사에서 신규 시작과 추가 전송을 거부한다.스위치 변경 요청 순간의 전역 즉시 차단은 아니다. 배포 반영 전·이미 허용 응답을 받은 진행 요청은 남을 수 있다. 직접 Sentry SDK를 호출하는 변조 클라이언트 차단 수단도 아니다.
내부 개별 삭제사용자 삭제 요청 접수는 제공하지 않는다. 담당자는 필요할 때 진단 번호로 해당 Replay를 확인하고 Sentry의 개별 삭제 기능을 사용할 수 있다. 실행한 삭제 작업과 확인 결과를 기록한다.철회와 삭제는 별개다. 복제본·백업까지 즉시 제거한다고 약속하지 않는다. 다른 일반 오류 이벤트를 함께 삭제하는 기능이 아니다.

현재 계정의 Team 요금제와 공식 데이터 유형별 표를 함께 대조해 새 Replay의 자동 보관 90일을 확인했다. 기존 데이터에는 수집 시점의 보관 기간이 적용된다. 7일 자동 삭제처럼 확인하지 않은 기능을 안내하지 않는다. 저장 IP 제거 설정도 전송 과정의 네트워크 IP 처리 자체를 없애지는 않는다.

운영 담당자는 Charlie Hyun이다. 실제 자동 보관 기간 90일과 현재 계정의 열람·삭제 권한은 확인했다. 사용자 삭제 요청 접수는 보류한다. 활성화 전 새 구현의 합성 Replay로 개별 삭제 후 조회 불가 여부를 검증한다. 삭제 실패 시 운영 스위치를 OFF로 전환하고 처리 결과를 확인한다.

삭제 기록은 담당자 로컬의 /Users/charlie.hyun/Library/Application Support/picnic-web/replay-operations/deletions.jsonl에 진단 번호·처리 일시·결과만 저장하는 안이다. 디렉터리 0700·파일 0600으로 제한하고 삭제 확인 후 30일에 기록도 지운다. 이 삭제는 활성 파일 대상이며 Time Machine 등 별도 백업의 사본까지 포함하지 않는다. 자동 삭제 작업이나 새 DB 테이블은 이번 범위에 만들지 않는다. 실제 Replay 식별자가 포함되는 비공개 운영 데이터이므로 Git 문서에 넣지 않는다. 이 경로의 파일은 아직 생성하지 않았다.

활성화 전에 대상 Sentry 프로젝트로 합성 Replay를 보내 저장된 user.ip_address, geo, browser/os/device 필드를 확인한다. IP·위치는 원문이 저장되지 않아야 한다. 저장되는 브라우저·OS·기기 정보는 안내 항목에 명시한다. 확인 결과와 맞지 않는 고지로 활성화하지 않는다.

현재 개인정보처리방침은 getPolicy('privacy', lang)로 외부 저장소에서 읽으므로 코드만으로 고지 내용을 확인할 수 없다. 담당자는 실제 방침에 Replay의 목적·항목·기간과 해당되는 처리 위탁·국외 이전 정보가 정확히 반영됐는지 확인한다. 이전받는 자·국가·항목·목적·보유 기간은 실제 설정과 계약으로 확인하고 필요한 내용을 반영한다. 이 문서는 법률 적합성을 판정하지 않으며, 방침 수정도 이번 작업에서 실행하지 않았다.

6. 승인 후 검증할 항목

검증합격 기준
기본 OFF와 동의운영 OFF, 미동의, 취소, 새로고침 직후, 비대상 경로에서는 recorder 시작과 Replay 전송 0회. 버튼·키보드로 안내 열기와 취소는 문서를 닫지 않고, 다시 열어 새 동의를 할 수 있다. SPA 도착·팝업·이미 닫힌 문서에는 동의 버튼이 없다. 기존 일반 오류 수집에는 회귀가 없다.
익명·광고로그인·불명확한 상태·Authorization·추가 쿠키·광고 허용·광고 로드 이력이 있으면 시작하지 않는다. 각 전송의 서버 검사 실패도 종료한다.
경합과 종료동의 클릭, SDK 로드 중 중지, worker 진행 중 중지, 자격 검사 중 철회, stop의 flush, 늦은 fetch 응답, 60초 경계, BFCache 복귀를 확인한다. 닫힌 세대에서는 추가 fetch가 없다.
용량·오류누적 8 MiB를 넘기는 envelope를 보내지 않는다. 2초 worker·1초 자격 검사·5초 전송 제한, overlap, 429, rate-limit 헤더, 실패 응답 후 종료를 확인한다.
데이터 경계payload에 텍스트·이미지·계정 정보·실제 URL·원본 오류·네트워크·콘솔이 없다. 일반 이벤트의 Replay 연계 필드 제거가 유지된다. Sentry가 추가하는 IP·위치·브라우저・OS・기기 필드는 저장 결과로 검사한다. 허용하지 않은 CSS는 종료한다.
호환성과 사용성실제 PC Chrome에서 동의→첫 전송 전 번호 표시→포인터·휠 스크롤·배너→중지를 검증한다. 페이지 이탈·탭 닫기·응답 유실 전에 번호가 표시됐는지 확인한다. 키보드 입력의 종료 규칙과 접근 가능한 안내를 확인한다. 지원하지 않는 브라우저는 수집하지 않는다.
배포와 manifest최종 배포 CSS·SDK·release·environment와 manifest가 일치한다. 불일치·검증 표식 부재 시 진입 UI는 OFF다. 새 Chrome 안정판에서 첫 segment와 연속 재생을 검증한다. Preview는 고정된 시험 origin·합성 데이터·시험 구성으로 검증하고 운영 origin 제한을 완화하지 않는다.
운영 중지와 삭제OFF 서버 배포 이후 다음 검사에서 중단됨을 확인한다. 이미 진행 중인 요청의 한계를 기록한다. 합성 Replay 개별 삭제·권한·실제 자동 보관 기간·수동 삭제 절차·고지 내용을 확인한다.

현재 합성 화면 저장·연속 재생과 운영 CSS 일치 검증은 완료되어 있다. 위 항목은 새 동의·운영 전송 기능의 검증이므로 기존 결과로 대체할 수 없다.
