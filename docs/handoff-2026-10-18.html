6. 이번 작업에서 확인한 함정

  • 공급자 HTTP status만으로는 클라이언트 오류를 가를 수 없다. 같은 400·422 안에 만료된 code와 설정 오류·공급자 장애가 함께 있다. 본문의 기계용 오류 코드를 허용 목록으로 본다. Google invalid_grant는 만료 code와 redirect 불일치를 가르지 않아 ERROR로 둔다.
  • 로그 레벨 시험은 Console target 줄로 본다. WARN은 console.warn에 WARN: <code>로, ERROR는 console.error에 ERROR: <code>로 끝난다. 기존 시험이 console.error만 읽으면 WARN으로 바뀐 경로를 놓친다.
  • 라우트 시험의 mock 호출 횟수가 시험 사이에 샌다. beforeEach에서 mockReset한다.
  • 진단 스크립트는 단위 시험에 포함되지 않는다. scripts/envelope-test/auth.js는 #141 뒤에도 500을 기대하고 있었다. 로그·응답 계약을 바꾸면 이 스크립트도 함께 확인한다. 실제 Next 빌드를 하므로 몇 분 걸린다.
  • Vercel 런타임 로그는 Pro 플랜에서 하루만 보존된다. MCP get_runtime_logs의 since는 23h 이하로 준다. 요청 단위 기록은 vercel logs --environment production --no-branch --since 24h --query <경로> --json으로 본다.
  • Codex 리뷰어 준비: Codex app-server의 capability 조회가 시간 초과(2: timeout)되면 한 번 다시 실행한다. Orca terminal send는 --enter로 제출한다. \r를 붙인 text는 입력만 되고 제출되지 않았다.
