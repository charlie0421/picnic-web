4. 현재 경계

  • 제품 app/·components/·lib/는 새 코드를 import하지 않는다. 운영 Replay는 꺼져 있다.
  • manifest는 BUILD_ID가 아니라 내용에 결합한다. CSS가 같은 배포는 같은 manifest를 쓴다. 다음 중 하나가 바뀌면 다시 만든다(spec §6.1): link CSS 자산, styled-jsx text, SDK·styled-jsx·Next 버전, viewport, 상태색.
  • accept에는 Chromium(Playwright 1.63.0) 변형만 있다. Safari·Firefox 사용자의 녹화는 종료한다.
  • 재생 화면은 Inter Fallback(Arial과 metric override)으로 그려진다. 재생하는 컴퓨터에 Inter가 있으면 그 글꼴이 쓰인다.
  • 계약은 범위 A(비로그인 /ko/vote ongoing 목록)만 다룬다.

  • Next가 바꾼 tsconfig.json·next-env.d.ts는 도구가 되돌린다. 끝난 뒤 git status를 확인한다.

6.3 이번 작업에서 확인한 함정

  • rrweb은 CSS의 url(/…)을 stylesheet origin의 절대 URL로 녹화한다. 그래서 계약이 origin을 정규화한다.
  • CSSOM 직렬화는 엔진마다 다르다. 글꼴 이름의 따옴표, 지원하지 않는 속성 제거, @font-face 서술자 순서가 다르다.
  • 원본 측정 전에 pointer를 화면 밖으로 옮긴다. 스크롤 뒤 pointer가 카드 위에 있으면 hover(4px)가 남는다.
  • 복원 페이지는 네트워크를 막는다. raw 기록에는 loopback 글꼴 URL이 있다.
  • 차단기는 소켓 연결 지점에서 검사한다. fetch·http 래퍼는 redirect, undici, 옵션의 호스트 덮어쓰기를 놓쳤다. NODE_OPTIONS preload는 worker thread와 자식 프로세스에도 적용된다.
  • HTML은 파서로 읽는다. 정규식은 따옴표 안의 >와 문자 참조를 놓쳤다.
  • docs/reports/는 .gitignore의 reports/에 걸렸다. 지금은 해결됐다. 커밋 52153026이 .gitignore에 !docs/reports/를 추가했다. 새 보고서는 git add -f 없이 추가한다.
  • 사용량 게이트: Codex 관측이 conflict이면 review-blocked가 반복된다. 2분 간격으로 다시 수집해 ready가 나온 5분 안에 진행한다. route=null과 maintenance는 ai-agent-config 설치 중이라는 뜻이므로 STOP한다. Codex app-server의 account/read가 시간 초과되면 5분 뒤 다시 시도한다.
  • Codex 리뷰어: build-orca-launch.py로 띄우면 리뷰어가 worker_done을 직접 보낸다. 판정 status 메시지와 worker_done이 따로 올 수 있으므로 delivery마다 처리하고 ack한다. 첫 화면의 “Set up security”는 Escape로 닫는다.
