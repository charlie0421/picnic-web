4. 판정 순서·스냅샷·시각

조정자의 설계 보완: VOLATILE+RC의 서로 다른 SELECT는 같은 snapshot이 아니다. 이를 “RPC 전체 한 시점”으로 표현하지 않는다. owner-first 조회와 불변 binding 무결성 확인 뒤, 변할 수 있는 order 상태·ORDER link·profile·현재 settings·상품·attempt 존재·REVIEW는 최종 단일 SELECT의 동일 snapshot으로 모은다. first-owner predicate를 이 조회에도 유지한다. 그 읽기가 끝난 뒤 clock_timestamp()를 한 번 취해 만료·판매창을 판정하고, 아래 우선순위로 저장된 판정값을 평가한다. 시각 취득 뒤 추가 mutable 조회를 끼우지 않는다. 이는 API 응답과 HTTP 전송을 원자화하는 계약이 아니다.

  1. RC가 아니면 위 격리 오류.
  2. order id AND user_id 조회 실패(null 포함) → NOT_FOUND. 그 전 다른 표를 읽지 않는다.
  3. context/key null 또는 binding hash가64자리 소문자 hex가 아니면 INPUT_INVALID.
  4. provider≠PAYPAL → PROVIDER_UNSUPPORTED. PortOne entry는 열지 않는다.
  5. 기존 binding read를 내부 호출한다. CONTEXT_REQUIRED/VERIFICATION_BINDING_REQUIRED는 같은 BLOCKED 사유. 손상 P0001은 그대로 전파한다.
  6. 저장 context/key≠입력 → CONTEXT_MISMATCH. 저장 binding hash≠입력 → BINDING_MISMATCH.
  7. 최종 상태 조회에 이 context/provider/environment의 ORDER link가 있으면 ORDER_LINKED. 아래 live 거부보다 우선한다.
  8. payment_state≠NOT_SUBMITTED, attempt 존재 또는 settlement_state≠NOT_INTAKE → ORDER_STATE_INVALID.
  9. profile 부재는 ENTRY_INVALID, deleted_at not null → ACTOR_DELETED. profile 부재는 원본 FK가 막는 경로인지 구분하며 내부 FK 해제로 fixture를 만들지 않는다.
  10. 현재 환경 settings 행 없음 → SETTINGS_UNAVAILABLE. environment≠order → ENVIRONMENT_MISMATCH.
  11. mode CLOSED 또는 allow_new_orders=false → ORDERS_CLOSED. allow_charge=false → CHARGE_CLOSED.
  12. 원본 gate 국가 식(PayPal KR 금지·허용 국가 배열) → COUNTRY_NOT_ALLOWED. INTERNAL/LIMITED actor 제외 → ACTOR_NOT_ALLOWED.
  13. 정책6개 중 null → POLICY_UNAVAILABLE. accepted_policy_version≠order → POLICY_NOT_ACCEPTED.
  14. 획득한 시각≥quote.expires_at → QUOTE_EXPIRED. 상품 consumable 아님/판매창 밖 → PRODUCT_UNAVAILABLE.
  15. REVIEW 존재 → REVIEW_REQUIRED. settings binding≠context → VERIFICATION_BINDING_CHANGED. 현재 scope≠context → PROVIDER_SCOPE_CHANGED.
  16. 그 밖에 AUTHORIZED.

정확21개 BLOCKED 사유: INPUT_INVALID, PROVIDER_UNSUPPORTED, CONTEXT_REQUIRED, VERIFICATION_BINDING_REQUIRED, CONTEXT_MISMATCH, BINDING_MISMATCH, ORDER_STATE_INVALID, ACTOR_DELETED, SETTINGS_UNAVAILABLE, ENVIRONMENT_MISMATCH, ORDERS_CLOSED, CHARGE_CLOSED, COUNTRY_NOT_ALLOWED, ACTOR_NOT_ALLOWED, POLICY_UNAVAILABLE, POLICY_NOT_ACCEPTED, QUOTE_EXPIRED, PRODUCT_UNAVAILABLE, REVIEW_REQUIRED, VERIFICATION_BINDING_CHANGED, PROVIDER_SCOPE_CHANGED. 사유들은 PE4·PE6·PE7이 분담한다. 원본 gate와 일부 거부 우선순위는 같지만 입력/context 선행·ORDER_LINKED 흡수·ORDERS_CLOSED 및 별도 quote 무결성 helper는 entry 계약의 선택이다. 원본 gate 전체와 순서/검증이 같다고 주장하지 않는다.

settings_version 동일성은 요구하지 않는다. 현재 필드들을 직접 비교하고 fresh context의 기존 version 검사는 prepare에 남긴다. drain(allow_new_orders=false, allow_charge=true)도 새로운 provider ORDER는 막는 보수적 기본값을 채택한다. 이는 prepare fresh의 existing 동작과 신규 진입 중지 요구에 맞춘 계획 선택이며 기존 link의 조회·capture gate 자체를 바꾸지 않는다.

5. 고정 key·응답 유실·동시성

create_request_key는 context의 불변 UUID다. 새 key·entry lease·row_version 증가를 만들지 않는다. entry_not_after=quote.expires_at이며 U2 소비자는 기존 before(d,timestamp,0)와 같은 경계로 만료 시 POST를 막는다. 양수 여유가 이미 존재한다고 주장하지 않는다. PayPal 멱등 보존 기간·동일 key 동시 응답은 미측정이다.

상황기대
타인/null/unknown다른 인수와 무관 NOT_FOUND exact3.
linked 뒤 중지/만료/탈퇴/REVIEW/회전동일 context/key/hash 입력에는 ORDER_LINKED. getter·binding read는 안전한 identity 조회를 유지.

9. U2 소비 경계 · 후속 W 구현 범위는 별도 확정

선후: U0 native→U2-A binding source/U2-D1 HTTP ACL은 U0-B와 독립이다. U0-B→U2-B entry client→U2-C create 배선→U2-D2 전체 실제 bridge 순서를 지킨다. 이 문서의 구현 승인 대상은 D4파일뿐이며 아래 W 경로·시험/실행기 전체 파일 목록은 다음 단위에서 확정한다.

제안 W 신규 binding-source.ts:
 createRpcChargeBindingSource(client:SupabaseClient):ChargeBindingSource
 consumes get_web_payment_provider_binding({p_actor_user_id,p_order_id})

BLOCKED REVIEW는 REVIEW, 그 밖에는 BLOCKED, 예외/불일치에는 UNAVAILABLE ENTRY다. 기존 context.failed code를 ENTRY에 재사용하고 registry는 고정한다. capture/reconcile/status에는 entry를 넣지 않는다. entry 거부/throw/echo불일치/흡수 때 create0 반례와 기존 성공 trail의 정확 entry 위치를 pin한다.

U2-D1/D2는 기존 pair와 바이트 검증 loader 경계를 재사용하는 새 source closure와 harness다. 옛 order-http WEB_HEAD=a67c9277/DB_HEAD=5a84abd9, charge-context-http DB_HEAD=e0ba366b와 manifest/guard는 현재 HEAD에서 그대로 실행할 수 없다. 옛 harness는 바꾸지 않는다.
