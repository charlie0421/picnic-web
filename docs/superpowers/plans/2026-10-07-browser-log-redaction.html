브라우저 로그 가림 — PR 5 구현 계획

승인: 2026-10-07. 구현자는 executing-plans와 test-driven-development를 적용한다. 전체 변경은 반대 공급자의 독립 리뷰를 받는다.

목표: 브라우저 오류·breadcrumb·transaction·span·Replay 전송에서 URL query와 fragment를 제거한다. Production Replay 표본율과 기존 외부 오류 필터는 유지한다.

설계: 기존 설계 §4.6. Sentry 9.47.1의 beforeAddRecordingEvent는 custom event에만 적용된다. rrweb Meta.href와 DOM 기록은 이 훅을 우회하고 Replay는 transport.send를 직접 호출한다. 따라서 일반 이벤트는 기존 scrubEvent/scrubSpan을 적용하고 Replay는 transport 경계에서 압축을 풀고 정제한 후 전송한다.

공통 조건

  • 운영 환경변수·비밀정보·DB·결제 호출을 사용하지 않는다. 테스트 수집기는 localhost에서만 실행한다.
  • 마스킹·샘플링·외부 오류 차단·지연 로드는 유지한다. Replay 활성화와 Sentry Data Scrubber는 범위 밖이다.
  • 불완전한 Replay payload·지원하지 않는 압축·크기 초과는 원문을 전송하지 않는다. 실패를 원문 로그로 기록하지 않는다.
  • 전송 응답·rate-limit 헤더를 보존한다. flush는 진행 중 정제를 기다리고 timeout을 지킨다.
  • 테스트 페이지는 scripts에만 보관하고 로컬 빌드 중에만 app/api/envelope-test에 복사한다.

작업과 검증

작업파일·검증 기준
1. 실제 브라우저 누출 재현scripts/envelope-test/browser.js와 browser fixture. 실제 Next production 빌드와 Chromium에서 오류·성능·breadcrumb·압축 Replay를 로컬로 수신한다. 각 종류의 수신을 먼저 확인하고 URL canary가 남아 실패하는 것을 기록한다.
2. 일반 이벤트 가림instrumentation-client.ts. beforeSend의 기존 필터 뒤에 scrubEvent, beforeSendTransaction·beforeSendSpan·beforeBreadcrumb에 공통 가림을 연결한다. 기존 필터 회귀 테스트와 브라우저 RED→GREEN을 검증한다.
3. Replay 전송 가림lib/sentry/browser-transport.ts, lib/sentry/replay-scrub.ts. createBrowserTransport(options)는 Sentry transport 계약을 반환한다. scrubReplayEnvelope(envelope)는 정제 사본 또는 null을 반환한다. 원본 envelope는 변경하지 않는다. JSON 구조·DOM ID·CSS 문법·UTF-8 길이를 보존한다.
4. 경계·회귀 검증__tests__/lib/sentry/browser-transport.test.ts. 압축/비압축·한국어·잘린 입력·초과 크기·압축 API 부재·전송 오류·동시 send와 flush timeout을 검증한다. 전체 Vitest, tsc, lint, 실제 브라우저 envelope를 실행한다.
5. 독립 리뷰와 PR최신 사용량·계정·capability로 Orca reviewer를 실행한다. 지적을 코드/테스트로 확인하고 원 리뷰어가 수정사항을 재검증한다. HTML 보고서를 커밋하고 PR·CI·Preview 결과를 확인한다. 머지는 별도 승인 후 진행한다.

리뷰 초점

  1. 압축 해제 중 과도한 메모리·대기 시간이 페이지와 flush를 막는가.
  2. Replay의 CSS·srcset·상대 URL에서 query를 지우면서 기록의 구조를 깨뜨리는가.
  3. 실패 또는 미지원 브라우저에서 원문이 전송되는가.
  4. 정제 비동기 작업을 flush가 놓치거나 후속 전송이 timeout 이후 시작되는가.
  5. 샘플링·외부 오류 필터가 달라져 오류를 누락하거나 정상 흐름을 오류로 수집하는가.
