Global Constraints

  • C: 분류 DB commit 전 장애는 정상 결제도 보류한다. intent commit 불명은 POST 권한이 아니다. capture POST 누계 1, 고정 멱등 key, 견적 15분을 유지한다.
  • 추가 capture POST·새 provider 주문·지급 권한은 만들지 않는다. PayPal COMPLETE, M1/account_id, credential resolver 개방, legacy 폐쇄, U4 UI, U5 PortOne, full T6는 범위 밖이다.
  • S0 CREATE와 S1 pre-intent GET는 barrier 밖이다. S1 assertion 저장 성공은 sticky지만 저장 실패·crash 뒤 나중 CLEAN→claim→POST→intake는 가능하다(R-PRE). R-CREATE/R-HTTP/R-WRITE 비용을 시험 결과에서도 보존한다.
  • grace 90초, cycle 45초. OPEN·expired OPEN은 pending, ABANDONED는 absence, 실제 adverse·assertion·conflict는 sticky다. pending/absence만으로 새 terminal REVIEW를 만들지 않는다.
  • 모든 receive는 wallet→order 잠금 아래 같은 admission을 쓴다. 기존 intake replay 우선은 유지하고 지급은 downstream이 다시 막는다. claim LOOKUP_ONLY와 entry ORDER_LINKED 우선순위는 유지한다.
  • READ COMMITTED만 지원한다. 잠금 뒤 별도 문장에서 hold를 평가한다. 세 attestation의 isolation 검사는 inline으로 넣고 기존 owner·명시 EXECUTE·membership을 보존한다.
  • W evidence 16-key/native allowlist 17-key를 구분한다. provider status·amount·merchant를 만들지 않는다. caller 판단은 SERVER_REPORTED assertion이다. RECORDED/RPC 성공은 CLEAN과 다르다.
  • 사실 ≤33(raw capture ≤32), caller assertion ≤8, DB code별 ≤1/최대7, 총 capacity ≤15. raw canonical octets ≤294912, 정규 request ≤16384, assertion detail ≤512. 개별 native evidence pg_column_size ≤8192는 그대로다.
  • 원 RPC 입력 hash·fact 순서·bind flag는 보존한다. E는 bind 전 snapshot으로 고정한다. O는 유효 단일 purchase_unit의 payments/captures 생략 또는 []이면 []; 형태 불명이면 null이다. CLEAN은 O non-null이며 CAPTURE fact ID 집합과 정확히 같아야 한다.
  • partial VOIDED는 실제 ORDER fact 또는 정확 UNRECORDABLE_PROVIDER_FACT assertion으로 정상 commit한다. 유효 adverse evidence는 nominal CLEAN 조건보다 먼저 effective ADVERSE로 처리한다.
  • 전역 observation lock bigint를 dedupe·오름차순 선취득한 뒤 원 fact 순서로 기록한다. bind=true는 CAPTURE 최대1개다. event는 기존 T7 UPDATE만, enroll만 INSERT한다. T7 lock 뒤 wallet/order lock을 잡지 않는다.
  • 구 PayPal claim은 NOT_CLAIMABLE/행0. 새 claim_v2는 모든 WEB_PURCHASE_V2 provider와 T10을 처리한다. T10 prepare 강제는 PAYPAL만이다. 구 PortOne 응답은 그대로며 새 worker에 raw fallback은 없다.
  • verification budget은 max(0,raw−hold RETRY 수), delay=min(300,2^clamp(budget,0,9)); hold delay=60초. queue backoff=min(21600,300×2^clamp(n,0,7)), 연속 횟수는 넓은 중간값에서 31로 포화한다. ownership counter는 재사용하지 않는다.
  • executor t0는 STARTED ACK 뒤, 새 claim cutoff는 t0+20초, provider 읽기 cutoff는 t0+55초. open 전 남은20초, open 뒤 실제 시간 재검사. 시작한 write는 RPC별10초까지 await한다. route/호출 timeout 120초는 운영 검증 전 제안이다.
  • absence release는 audited basis/version/현재 CLEAN cycle 단위다. runtime EXECUTE·permission 부여 0, actual ADVERSE 해제 0. OG1–OG6는 계속 닫혀 있다.
  • 모든 실행 연결은 disposable 환경에만 한다. 로그·DTO·outcome·오류·경보에 lease/cycle token·credential·PII를 넣지 않는다. HTTP와 DB의 원자성은 주장하지 않는다.
