KG이니시스 등 PG 통합창웹 서버가 해당 채널에 설정한 payMethod로 창을 연다. 카드 창에서 고객이 간편결제를 골라도 서버가 확인한 실제 수단으로 정산한다. 계좌이체·가상계좌·휴대폰·상품권은 해당 PG가 정한 호출 방식과 가맹점 계약을 따른다. KG 모바일 상품권 결제에는 상품권 종류가 필요하다. 포트원 KG이니시스 안내

수동 승인포트원 콘솔에서 해당 채널의 수동 승인을 설정해야 한다. 인증이 끝나면 웹 서버가 같은 주문에 승인 요청을 한 번 보낸다. 가상계좌는 이때 발급된다. 별사탕 지급은 입금을 확인한 뒤에 진행한다. 포트원 수동 승인 안내

웹 서버는 PORTONE_HOSTED_CHANNELS에서 주문에 고정한 환경·채널·설정 버전을 찾는다. 복귀 서명에는 PORTONE_HOSTED_CONTINUATION_SECRET을 사용한다. 웹훅 서명 키는 TEST와 LIVE에 따로 둔다. DB 정산 작업자는 PORTONE_HOSTED_CREDENTIALS에서 같은 주문의 자격 증명을 찾으므로 결제창을 닫은 뒤에도 과거 주문을 처리할 수 있다.

일반 회원용 LIVE 구매 버튼에는 NEXT_PUBLIC_PORTONE_HOSTED_CHECKOUT_ENABLED와 NEXT_PUBLIC_PORTONE_HOSTED_CUSTOMER_CHECKOUT_ENABLED가 모두 필요하다. 웹 서버는 PORTONE_HOSTED_DOWNSTREAM_ENVIRONMENTS, DB의 복구 가능 상태, 주문별 구매 자격을 확인한 뒤 결제창을 연다. TEST는 관리자 계정을 사용한다. 실제 운영에는 환경별 정산 작업자 실행, 자격 증명 등록과 가맹점 채널 개통이 필요하다.

격리 DB에서 모의 포트원 응답으로 카드·계좌이체·가상계좌·휴대폰·상품권·편의점·간편결제의 지급과 전액 환불을 확인했다. 간편결제에는 카카오페이와 네이버페이 응답을 사용했다. TEST와 LIVE 각각에서 100개와 보너스 7개가 한 번 지급되고, 같은 거래를 전액 취소하면 107개가 한 번 회수됐다. 지급 후 100개를 쓴 시험에서는 남은 7개가 지갑에서 회수되고 100개가 회수 채무로 기록됐다.

1,700원 주문에 200원 할인 또는 1,700원 전액 포인트를 적용한 경우도 시험했다. 실제 결제액과 할인액의 합이 주문 금액과 일치하면 주문에 정한 107개를 지급한다. 전액 취소의 금액 구성이 원거래와 일치하면 107개를 회수한다. 지급 전에 두 번 조회한 금액 구성이 서로 달랐던 시험에서는 지급 0건을 확인했다.

웹과 DB 연결 시험은 운영 코드의 승인·조회 함수에 격리 DB를 연결하고 포트원 응답을 모의했다. TEST에서는 카드 창에서 카카오페이를 선택한 주문을, LIVE에서는 카카오페이 전용 창 주문을 사용했다. 같은 인증 결과를 두 번 전달해도 승인 요청은 한 번이었다. DB 작업자는 웹이 기록한 결제 사실을 다시 확인해 지급했고, 전액 취소 후 같은 주문의 별사탕을 회수했다.

모바일 인증 후 피크닉으로 돌아왔을 때 로그인 세션이 만료됐으면, 다시 로그인해 원래 주문을 조회한다. 승인 요청이 접수되기 전이라고 서버가 확인한 경우에만 고객이 같은 주문의 결제창을 다시 열 수 있다. 승인 응답이 8초 안에 오지 않으면 주문 조회 화면으로 돌아간다. 승인 토큰은 브라우저 저장소에 보관하지 않는다.

가상계좌 시험에서는 발급 직후 잔액이 0이었다. 주문 견적의 유효시간이 지난 뒤 입금을 확인하자 원래 주문 조건으로 지급됐다. 웹훅은 재조회를 시작하는 신호로 사용한다. 주문 금액, 입금 시각, 이미 확인한 입금 기한을 대조하는 근거는 서버가 조회한 결제 정보다.
