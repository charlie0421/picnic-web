Error.prepareStackTrace 를 잠깐 바꿔 구조화된 호출 지점(CallSite)을 받고, 스크립트 이름·줄·칸만으로 stack 을 만든다. 이 API 가 없는 엔진에서는 프레임을 싣지 않는다. 문자열을 거르는 방법은 쓰지 않았다 — 함수 이름에 줄바꿈을 넣으면 위치처럼 생긴 줄을 만들 수 있다 "호출부의 함수 이름이 값에서 온 것이어도 새지 않는다" 4건(computed 메서드, 값을 키로 삼은 호출, 줄바꿈으로 위치를 흉내 낸 이름, 동적 클래스 이름), "stack 에는 위치만 싣는다" 1건

9. 값을 치르고 배운 것 — 틀렸던 것 6건

틀렸던 것실제왜 놓쳤고 무엇이 잡았나
"콜백의 console.log 줄이 Vercel 로그로 나간다"운영 빌드는 compiler.removeConsole 로 console.log·info·debug 를 지운다. 운영에서 나가는 것은 console.error·warn 과 logError 다소스의 줄만 보고 빌드 산출물을 보지 않았다. envelope 테스트의 라우트가 찍은 console.log 가 서버 출력에 나오지 않아 알았다
"Replay 오류 표본율이 1.0 이다"Production 번들의 값은 세션 0, 오류 0 이다코드의 기본값만 봤다. 배포된 번들을 내려받아 확인했다
"await import 때문에 이벤트가 flush 보다 늦게 큐에 들어갈 수 있다"틈이 없다. 동적 import 는 마이크로태스크만으로 풀리고 flush 는 1ms 타이머로 처음 확인한다설계가 "고치기 전에 먼저 재라, 실패하지 않으면 가설이 틀린 것"이라고 적어 둔 덕에 고치기 전에 알았다
전달 시나리오가 통과했으니 틈을 잡는 테스트다일부러 5ms 지연을 넣으니 다섯 단계 가운데 넷만 실패했다. 수집기가 client_report 까지 늦게 답해, 틈이 몇 ms 차이로만 드러났다통과하는 것만 봤으면 몰랐다. "틈을 만들어 실패를 본다" 단계가 잡았다. 수집기가 오류 이벤트에만 늦게 답하게 고쳐 차이를 약 300ms 로 벌렸다
"호출 지점에서 만든 stack 에는 요청의 값이 들어갈 길이 없다"함수 이름은 값에서 올 수 있다({ [action]() { … } })설계서에 적은 문장을 그대로 믿었다. 교차 리뷰가 잡았다
경계 함수는 무엇이 던져져도 안전하다던진 값을 unstable_rethrow 가 들여다보다가 난 예외가 그대로 밖으로 나갔다"넘겨받은 값은 무엇이든 될 수 있다"를 계약 함수에는 적용하고 경계 함수의 첫 줄에는 적용하지 않았다. 교차 리뷰가 잡았고 실제 서버에서 재현됐다

10. 함정

  • 로컬 실행이 운영 Sentry 로 보고된다. .env.local 에 운영 DSN 이 있다. 오류를 일부러 내는 실험과 로컬 빌드는 SENTRY_DSN= NEXT_PUBLIC_SENTRY_DSN= 로 한다. envelope 테스트는 DSN 을 로컬 수집기로 돌리므로 그대로 써도 된다.
  • envelope 테스트는 CI 에서 돌지 않는다. 빌드가 Supabase 조회에 의존한다. Sentry SDK 를 올리거나 sentry.*.config.js, utils/logger*.ts, utils/log-safe-error.ts, utils/with-safe-errors.ts 를 고치면 로컬에서 돌리고 결과를 PR 에 적는다. 한 번에 4~5분이다.
  • envelope 실행기가 중간에 죽으면 app/api/envelope-test/ 가 남을 수 있다. 남아 있으면 지운다(운영 빌드의 postbuild 검사와 단위 테스트가 잡는다). 빌드 중에 next-env.d.ts·tsconfig.json 이 잠깐 바뀌었다가 되돌아온다.
  • 통과만 본 테스트를 믿지 않는다. 지금 성립하는 성질을 고정하는 테스트는 처음부터 통과한다. 코드를 일부러 망가뜨려 실패하는지 본다(§9 의 4번).
  • 서버 전용 코드의 테스트는 // @vitest-environment node 로 돈다(#121 이 공용 setup 의 window 사용부를 가드로 감쌌다). jsdom 에서는 next/navigation 이 브라우저용 unstable_rethrow 를 골라 동적 렌더링 신호를 올려보내지 않는다.
  • vitest 에서 시간을 재는 테스트는 한 번 돌려 둔 뒤에 잰다. 처음 도는 코드는 느려서 그 사이에 늦은 기록이 flush 를 따라잡는다 — 틈이 있어도 가려진다.
  • CI 는 UTC 에서 돈다. 날짜를 다루는 테스트는 PR 전에 TZ=UTC 로도 돌린다.
  • 리뷰 요청의 mode. 이미 구현한 것을 리뷰만 받을 때는 사용량 게이트의 첫 인자를 claude-heavy 로 준다. auto 는 주간 사용률에 따라 codex-heavy 를 골라 리뷰어가 Claude 로 잡히고 launch 가 거부된다.
  • 읽기 전용 Codex 리뷰어는 worker_done 을 보내지 못한다(샌드박스가 막는다). 마지막 턴이 판정으로 끝난 것을 transcript 로 확인한 뒤 worker-abandon 으로 정산한다. 터미널을 닫아 끝내지 않는다.
  • Codex 가 처음 뜰 때 보안 설정 안내 카드가 나올 수 있다. 번호를 고르지 않고 Esc 로 닫는다. 그 상태에서 지시를 보내면 삼켜질 수 있으니 /status 로 모델·effort·권한을 먼저 확인한다.
